# Web-MVP research: Brig как основа Rails/Phoenix-подобного фреймворка

Исследование: что нужно языку, рантайму, stdlib и тулчейну Brig, чтобы на
нём было быстро писать и дёшево поддерживать веб-приложения и сервисы,
**не теряя главного свойства — поставки одним файлом**. Плюс фантазийный
проект на ещё не существующем фреймворке **Calmar** и однофайловый сервис на
микро-фреймворке **Whelk**.

Спеку и код это исследование не меняет. Решения приняты (таблица — в
[07](07-open-questions.md)); внесение в спеку — задачи с меткой `edit-spec`
(первая — #169), состав остальных ещё обсуждается.

## Ключевые выводы

1. **Позиционирование:** «надёжность Phoenix + дистрибуция Go + скорость
   разработки Rails». Один файл — и для `brig`, и для собранного
   приложения. Вторичные ниши — серверный скриптинг и edge/embedded (Linux-класс).
2. **Инварианты одного файла:** без cgo, stdlib внутри бинарника
   (`go:embed`), приложение = рантайм + payload, бюджет ≤ 25 МБ (оценка
   с SQLite и TLS — 12–15 МБ).
3. **Главная находка — Q-await:** без selective receive любая библиотечная
   функция с `recv` внутри (HTTP-клиент, `call`, SQL) съедает чужие
   сообщения вызывающего актора. Решение — `await(ref, timeout)` с
   ref-слотами: O(1), ящик не трогается, §16 по сути не нарушается.
4. **I/O = порты, только pull-режим** (active-once): backpressure без новых
   механизмов, один режим, владение сокетом без гонок, iodata для записи.
5. **Run-loop должен ждать внешние события**, а не завершаться — меняется
   детекция «все заблокированы» и появляется гарантия G5 в §15.
6. **Supervisor — механизм в ядре, политика в библиотеке:** VM даёт `exit`,
   `spawn_watched`, реестр имён, `Global`, таймеры, время; `Supervisor` и
   `Server` пишутся на Brig.
7. **Язык: нужны без нового синтаксиса** — многофайловые модули, `rec.field`,
   модули/типы как значения (это уже требует MFA в §13.1). **С одним
   словом** — `pub fn`. Kwargs и макросы не нужны: опции — анонимные
   записи со спредом, роутер — данные.
8. **Полиморфизм по данным — через «модуль типа»** (`Monitor.to_json`),
   а не протоколы: ноль синтаксиса, фиксированный набор имён в stdlib.
9. **Шаблоны — отдельные файлы `.html.bt`**, компилируемые тулчейном, с
   авто-экранированием: это не макросы и не сигилы, но и не XSS «из коробки».
10. **HTTP: транспорт — Go `net/http` (HTTP/1.1 + HTTP/2 + TLS), семантика —
    Brig** (`Conn`, плаги, роутинг; B2). SQL/PubSub/Supervisor — stdlib на Brig; VM о них не знает;
    SQLite (pure-Go) встроен по умолчанию, Postgres — пакет.
11. **Фреймворк: чистое ядро, акторная оболочка.** Обработчик — `Conn -> Conn`,
    конвейер останавливается, как только задан ответ; всё долгоживущее —
    акторы. SSE/стриминг — обычный `recv`-цикл в акторе запроса.
12. **Тестируемость — архитектурное требование:** фейковые часы и in-memory
    транспорт в VM дают детерминированные интеграционные тесты без сети.
13. **Уточнения спеки, найденные в demo:** вид записи при `{ ..m, f: v }`
    (§4.7 противоречив), `_ <-` глотает ошибки, `m["k"]` → `Option` мешает
    навигации по JSON, `recv … after` не годится для периодических задач,
    §12.4 разрешает `_msg`, а лексер — нет, у опровержимого `=` нет
    семантики. Все решены: L16–L21.
14. **Пакетный менеджер обязателен с первого релиза.** Пакеты — только
    Brig-исходники (никакого Go/C) — это сохраняет «один файл» и
    кросс-компиляцию. Git + MVS + lock; Calmar — обычный пакет, без
    офлайн-снапшота внутри `brig`.
15. **Контракты — гибрид code-first (утверждено):** типы Brig — источник
    истины; глубокая проверка один раз на границе (`decode_as`), внутри —
    O(1)-проверка номинального тега на `pub fn`; JSON Schema/OpenAPI
    экспортируются из типов, чужие схемы импортируются. Иммутабельность
    делает проверенную запись доказательством.
16. **Пакеты (утверждено):** менеджер — подкоманды `brig` (`brig add`,
    `brig install`), пакеты — только Brig-исходники, URL как идентификатор
    только в манифесте, MVS, одна мажорная версия на сборку, права как в
    Deno — для зависимостей, Chandler — необязательный индекс и кэширующий прокси. Calmar —
    отдельный пакет со своим лаунчером `calmar new`.
17. **Память (B7):** общий heap остаётся до замеров; защита — бюджет «хода»
    актора с `exit` по превышению, счётчики, `GOMEMLIMIT`; при встраивании —
    лимиты на экземпляр рантайма. Шесть инвариантов держат heap на актора
    возможным; решение — по замерам до 1.0.
18. **Блок B (утверждено):** автоматический HTTPS в web-MVP; аналога ETS
    нет (шардированные акторы + `Global`); симуляционное тестирование —
    стратегическая цель; 0.x с `brig fix`, 1.0 — совместимость как Go 1;
    WASM-песочница после релиза языка, ядро VM без ОС-зависимостей.
19. **Блоки C и D (утверждено):** tz-база в бинарнике; загрузки потоком с
    временными файлами; почта и переводы — пакеты, плюрализация — stdlib;
    фоновые задания — пакет после MVP; деплой — `SO_REUSEPORT` + drain;
    `brig observe` к MVP; import maps сейчас, серверный UI — стратегия;
    Linux/macOS tier 1, Windows tier 2; MIT везде; первые пакеты —
    Postgres и Mailer.
20. **Данные (утверждено):** data mapper в духе Ecto — запрос как
    неизменяемое значение, I/O только в `Repo`, явный `preload` (N+1
    невозможен), без ActiveRecord; отдельный пакет после MVP.
21. **Порядок:** закрыть Wave 6 → проектная база (модули, stdlib на Brig) →
    рантайм-механизмы (сразу закрывают нишу скриптинга) → сеть → Calmar.
