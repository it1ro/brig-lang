# 01. Позиционирование: один файл как киллерфича

## Тезис

Brig конкурирует не синтаксисом, а **формой поставки и моделью исполнения**:

> Один статический бинарник `brig` (≈10–20 МБ), в котором язык, акторный
> рантайм, stdlib с батарейками, тулчейн и веб-стек. Приложение собирается
> в ещё один такой же файл. Скопировал — запустил. Ни Docker-образа с
> рантаймом, ни `node_modules`, ни `bundle install`, ни Erlang/OTP на хосте.

Вторая киллерфича — **автоматический HTTPS** (B1): `./app --domain
example.com` сам получает и продлевает сертификат. Один файл на голом VPS,
без nginx и certbot. Третья — **детерминированное симуляционное
тестирование** акторной системы (B4), которого нет у мейнстримных
веб-стеков.

Сейчас это уже почти правда: `bin/brig` — статически слинкованный Go ELF,
5.7 МБ, без cgo. Задача — **не потерять это свойство** по мере роста.

## Сравнение с ближайшими

| | Поставка рантайма | Поставка приложения | Конкурентность | Где Brig выигрывает |
|---|---|---|---|---|
| Elixir/Phoenix | Erlang/OTP + Elixir + mix | release-директория (ERTS внутри), не один файл | процессы BEAM | один файл, старт за мс, скриптинг |
| Rails | Ruby + gems + часто node | образ/директория | потоки + Sidekiq/Redis | нет Redis/Sidekiq: фон = акторы |
| Go (net/http) | не нужен | один файл | goroutines + общая память | иммутабельность, супервизия, выразительность |
| Deno/Bun | один файл | `compile` → один файл | event loop, async/await | нет async-раскраски, изоляция падений |
| Lua/OpenResty | nginx + LuaJIT | скрипты | корутины | целостная модель, не встраивание в nginx |

Ниша: **«Phoenix-надёжность с Go-дистрибуцией и Ruby-скоростью разработки»**.

## Три ниши и что каждая требует

| Ниша | Сценарий | Критичное требование |
|---|---|---|
| **Веб / сервисы** | API, SSR-сайт, внутренние сервисы, webhooks, SSE/WebSocket | HTTP-порты на Go `net/http` + семантика на Brig, супервизия, хранилище, graceful shutdown |
| **Серверный скриптинг** | замена bash/python на серверах: деплой-скрипты, cron, обработка логов, glue | старт < 20 мс, shebang, fs/proc/env, стримы stdin/stdout, нет установки зависимостей |
| **Embedded / edge** | роутеры, SBC (ARM/RISC-V), шлюзы IoT, агенты мониторинга | кросс-компиляция одной командой, малый RSS, нет cgo, порты для serial/GPIO, устойчивость к падениям (супервизия) |

«Embed» трактуем двояко, оба смысла ценны:
1. **Embedded-устройства** — Brig как рантайм на слабом железе (Linux-класс,
   не микроконтроллеры: Go-рантайм требует MMU и ~десятки МБ RAM).
2. **Встраивание в Go-хост** — `import "brig"` как скриптовый движок
   (конфиги-как-код, плагины, правила). Следствие реализации на Go, почти
   бесплатно, если держать чистый API `vm`.

## Инварианты «одного файла» (правила для всех решений)

1. **Без cgo.** Любая зависимость — чистый Go. SQLite — только pure-Go порт
   (например, `modernc.org/sqlite`) или отказ; TLS — `crypto/tls`.
2. **Stdlib внутри бинарника.** Brig-часть stdlib встраивается через
   `go:embed` и компилируется (или хранится предкомпилированной) внутри.
   Никакого `$BRIG_HOME/lib`.
3. **Приложение = один файл.** `brig build` склеивает рантайм + байткод
   приложения + ассеты (`priv/`, шаблоны, миграции) в исполняемый файл.
4. **Бюджет размера.** Цель ≤ 25 МБ для `brig` со всеми батарейками; каждая
   новая Go-зависимость > 1 МБ — осознанное решение с замером.
5. **Кросс-компиляция тривиальна.** `brig build --target linux/arm64` работает
   с любого хоста (у Go это бесплатно, пока нет cgo).
6. **Конфиг не требует файлов рядом.** Дефолты в бинарнике, переопределение
   через env / флаги / опциональный файл.

## Чего сознательно не делаем

- Не становимся универсальным языком «для всего»: GUI, data science, ML —
  вне фокуса.
- Не гонимся за пиковой производительностью Go/Rust: интерпретатор с
  регистровой VM; цель — «достаточно быстро для типичного веба» (десятки
  тысяч простых req/s на ядро — ориентир, не обещание).
- Не встраиваем в VM протоколы (HTTP, WebSocket): только механизмы.
- Не делаем распределённость (кластер нод) в web-MVP: PID уже резервирует
  node-поле, этого достаточно.
- Не тащим JS-тулчейн: ассеты — статика; фронтенд-сборка — вне `brig`.
