# 03. Язык: пробелы для фреймворка

Смотрим на язык глазами автора фреймворка и автора приложения. Каждый
пункт — сценарий, где без изменения больно. Уровни: M/S/N для web-MVP.

## L1. Незакрытый Must (Wave 6) + offside внутри скобок — M

Компиляция `match` (T-70), `with` (T-71), pipe (T-72), записи (T-73),
record-паттерны (T-74). Без них ни pipeline над `conn`, ни контроллеры не
пишутся. Это **предусловие**, а не часть web-работы.

Плюс **offside внутри скобок** (issue #2, A5.4): блочная лямбда как
аргумент вызова — `Test.it("…", fn () -> <блок>)`,
`Repo.transaction(fn (tx) -> <блок>)`, `Supervisor.start({ … on_start: … })`.
Во фреймворке это повсюду; `brig check` на demo падает именно на этом.

## L2. Многофайловые модули — M

**Факт:** `import` парсится, но загрузчика модулей нет. Приложение из
десятков файлов без этого не существует.
**Нужно:** резолв по правилу §11.1 (`lib/lookout/checker.brig` →
`Lookout.Checker`), кэш байткода, детект циклов (циклы импорта модулей
функций безвредны — разрешить; ошибка только для несуществующих имён).
Тот же механизм грузит **встроенный stdlib** из `go:embed`.

## L3. Видимость функций — M

**Сценарий:** поддерживаемость. В большом приложении нужно отличать API
модуля от внутренностей; сейчас в спеке все `fn` публичны.
**Варианты:** `pub fn` / приватное по умолчанию; или `fn _helper` по
соглашению (проверяется компилятором). → Q-vis в 07.
Рекомендация: **приватно по умолчанию, `pub fn` для экспорта** — явное
лучше неявного (§0.3), дешёвая проверка в sema.

## L4. Доступ к полям записи — M

Грамматика уже даёт `postfix "." LOWER_IDENT`, но семантика для записей
не описана. Нужно: `conn.status`, `user.email`; отсутствующее поле —
`raise((:no_field, (name, value)))` (авто-raise, как `:case_clause`).
Никакого `Option` на каждый доступ — для необязательных полей используется
`Option` как значение поля.

## L5. Модули и типы как значения — M

**Сценарий:** `resources("/monitors", MonitorController)`,
`Repo.all(Monitor)`, `Json.decode_as(Monitor, body)`, и уже в спеке — MFA
`{ module: M, function: F, args: A }` (§13.1). Спека неявно требует
модуль-значение, но нигде его не определяет.
**Предложение:** `UPPER_IDENT`-путь в позиции выражения → значение вида
`Module` (identity = полное имя; сериализуется как строка имени, что и
нужно для MFA). Операции: `Module.apply(m, :fn_name, args)`,
`Module.exports(m)`, `Module.has(m, :fn, arity)`. Тип записи — тоже
значение (`Monitor` как тип даёт `Type.fields(Monitor)`).
Это **не** делает модули stateful (§0.5 цел): значение — лишь имя.
→ Q-mod в 07.

## L6. Полиморфизм по данным — S (M для JSON/HTML)

**Сценарий:** `Json.encode(monitor)` должен скрыть `password_hash`;
шаблон должен уметь вывести `Money`/`Instant`; роутер — превратить запись
в `/monitors/42`. `Behavior` в спеке — про акторы, не про данные.
**Варианты:**
1. без полиморфизма — всегда явные функции (`Monitor.to_json(m)`);
2. **конвенция «модуль типа»**: номинальная запись `Monitor{..}` несёт имя
   типа; `Json.encode` проверяет `Monitor.to_json/1` в модуле, где тип
   объявлен, и вызывает её, иначе кодирует поля;
3. протоколы как в Elixir (`protocol`/`impl`) — новая конструкция.

Рекомендация: **вариант 2** — ноль нового синтаксиса, единообразно для
`to_json`, `to_param`, `to_html`, `to_str`; требует L5. → Q-poly в 07.

## L7. Опции без kwargs — S

kwargs в §16 = Should. Для фреймворка хватает **анонимной записи
последним аргументом** + спред дефолтов:

```brig
fn listen(port, opts) ->
    o = { ..default_listen_opts(), ..opts }
    ...
Http.listen(4000, { acceptors: 16, max_body: 8_000_000 })
```

Рекомендация: kwargs **не вводить** (один способ, §0.2). Нужна гарантия,
что `{ ..a, ..b }` — правый побеждает (есть в §5.2 по смыслу, явно
зафиксировать).

## L8. Строки и байты — M

Факт: в прелюдии только `Bytes.to_str`, `Str.to_bytes`.
Нужно (Go-native, быстрые):
- `Bytes`: `slice` (O(1), общий буфер — безопасно из-за иммутабельности),
  `find`, `split`, `starts_with`, `concat`, `at`, `to_int` (ASCII-цифры),
  `lower_ascii`.
- `Str`: `split`, `join`, `trim`, `find`, `replace`, `starts_with`,
  `ends_with`, `lower`/`upper`, `slice` по кодпоинтам, `pad`, `to_int`.
- Кодеки: `Base64`, `Url` (percent-encoding, query), `Hex`, `Html.escape`.

## L9. Многострочные строки — M (сейчас Should)

SQL, фикстуры, письма, help-тексты в скриптах. §3.5 уже есть в спеке —
перевести в Must для web-профиля.

## L10. Шаблоны без макросов и сигилов — M для SSR

**Проблема:** макросов нет (§16), пользовательских сигилов нет (§3.2),
интерполяция `\(...)` в `Str` не экранирует → XSS «из коробки».
**Варианты:**
1. HTML как функции/данные (`div({ class: "x" }, [...])`) — чисто, но
   вёрстка нечитаема для дизайнера;
2. **файлы шаблонов, компилируемые тулчейном** (`*.html.bt` →
   Brig-функции модуля) с авто-экранированием и типом `Html.Safe`;
3. рантайм-шаблонизатор (парсинг строки при запуске) — медленнее,
   ошибки только в рантайме.

Рекомендация: **2**. Это не макрос: шаблон — отдельный язык разметки со
вставками выражений Brig; тулчейн генерирует модуль до компиляции.
Цена — ещё один парсер в бинарнике (маленький). → Q-tpl в 07.

## L11. Рефлексия номинальных типов — S

`Type.fields(Monitor) -> [:id, :url, ...]` — формы, маппинг строк БД в
записи, `Json.decode_as`. Требует L5. Аннотации полей остаются
документацией; валидация — библиотечная (changeset).

## L11a. Аннотации становятся контрактами — M (решение: 09)

§14.4 «documentation-only» заменяется: аннотации проверяются на входе
`pub fn` (O(1): вид/тег) и глубоко в `decode_as`. Подробности, цена и
отображение в JSON Schema — [09-contracts.md](09-contracts.md).

## L12. Время, даты, деньги — S

`Instant`, `Date`, `Duration` — номинальные записи stdlib с Go-реализацией
форматирования/парсинга (RFC 3339, HTTP-date). `Decimal` (уже Should) —
Must для денег, если фреймворк претендует на Rails-нишу.

## L13. Or-паттерны — N

`(:get | :head)` в роутере удобно, но обходится мультиклозными `fn`.

## L14. Конвенция ошибок — M (без изменений языка)

Фреймворку нужна единая форма доменных ошибок, чтобы маппить в HTTP:
`Error((:not_found, detail))`, `Error((:invalid, errors))`,
`Error((:forbidden, detail))`, `Error((:conflict, detail))`. `raise` внутри
обработчика → 500: connection-актор оборачивает handler в `trap`. Это
соглашение фреймворка, язык менять не нужно.

## L15. Горячая перезагрузка — N (dev-reload — S)

Для разработки достаточно перезапуска VM в том же процессе при изменении
файла (старт в мс). Hot code upgrade в проде — не нужен для MVP.

## L16. Навигация по вложенным данным — S

`m["k"]` возвращает `Option` (§4.5) — это правильно, но
`resp.json["data"]["id"]` не пишется: индекс по `Option`. JSON-ответы,
params форм, конфиги — сплошь вложенные мапы.
Предложение без нового синтаксиса: `Json.at(v, ["data", 0, "id"]) ->
Option` (путь из ключей и индексов) и `Map.get_or(m, k, default)`.
Альтернатива — оператор `?.`-типа: отвергаем (новый синтаксис, §0.1).

## L17. `_ <-` в `with` глотает ошибки — S (линт)

Спека сама рекомендует `_ <- log(a)` для побочных эффектов (§8.2). Но
`_ <- Repo.exec(...)` молча пропускает `Error(...)` — транзакция
закоммитится. В demo эта ошибка была сделана и исправлена трижды.
Предложение: info-диагностика sema, если справа от `_ <-` вызов, который
по соглашению возвращает `Result` (имя в stdlib-таблице или аннотация
`-> Result<…>`); рекомендовать `Ok(_) <-`.

## L18. Record update и вид записи — M (уточнение спеки)

§4.7: «Конвертация: `{ ..u }`, `User{ ..r }`. Record update сохраняет вид».
Непонятно, что даёт `{ ..m, status: :up }` для номинального `m`: анонимную
запись («конвертация») или `Monitor` («сохраняет вид»)? Для фреймворка
критично (Conn — номинальный, обновляется постоянно).
Предложение: `{ ..m, f: v }` **сохраняет вид** первого спреда; конвертация
в анонимную — явная `Record.to_anon(m)`. В demo везде явно `Monitor{ ..m, … }`.

## L19. Имя типа vs имя модуля — M

Тип `Monitor` объявлен в модуле `Lookout.Monitors.Monitor`. Как сослаться
на тип снаружи: `Lookout.Monitors.Monitor.Monitor{…}`? Предложение
(как в Elixir): если последний сегмент модуля совпадает с именем типа,
после `import`/`alias` имя `Monitor` означает тип (и модуль для
«модуля типа», L6). → Q-typename в 07.

## L20. `_name` — расхождение спеки и лексера — S

§12.4 предлагает `else _msg`, «если имя не нужно», а лексер отвергает
идентификаторы с `_` в начале (`identifier must not start with '_'`,
найдено `brig check` на demo: `fn index(conn, _params)`). Для фреймворка
неиспользуемые, но документирующие имена параметров (`_params`, `_conn`)
важны для читаемости сигнатур действий. Решить: разрешить `_name` как
«именованный wildcard» (не связывается) или убрать упоминание из §12.4.

## L21. Опровержимый паттерн в `=` — M (уточнение спеки + компилятор)

Грамматика разрешает `let_bind ::= pattern "=" expr`, но спека не
определяет, что происходит при несовпадении: в списке авто-raise (§10.4)
нет подходящего имени. Компилятор сейчас принимает только `name = expr`
(«срез: только простые связывания»). Демо опирается на идиому «let it
crash»: `Ok(_) = Monitors.record_check(event)`, `Some(id) = Json.at(…)`.
Предложение: несовпадение → авто-raise `(:badmatch, value)`; добавить в
§10.4; реализовать в компиляторе. Неопровержимые паттерны (`(a, b) = t`,
`{ json: j } = resp`) — частный случай.
