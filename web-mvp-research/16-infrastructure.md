# 16. Инфраструктура приложения

Решения по сквозным механизмам, которые меняют дизайн рантайма и stdlib:
тесты с БД, сериализация значений, инструментирование, команды проекта и
релиза (аналог rake).

## 1. Тесты с БД и акторами (утверждено 2026-09-27)

**Проблема.** Тест создаёт монитор, а в БД пишет чекер — другой актор.
Модель Ecto (тест владеет транзакцией и одалживает её через `allow`)
хрупкая, а у нас есть второе препятствие: реестр имён (`:repo`, `:pubsub`)
глобален в рантайме, и параллельные тесты столкнутся на именах ещё до БД.

**Решение: экземпляр рантайма на тест** (механизм 11/M4):

| Что | Как |
|---|---|
| Единица изоляции | отдельный экземпляр рантайма: свой реестр, `Global`, фейковые часы, in-memory транспорт (R9), своя БД. Все акторы экземпляра и есть тест — `allow` не нужен |
| Параллелизм | экземпляры в разных горутинах ⇒ тесты параллельны на всех ядрах |
| SQLite | миграции один раз в шаблонную `:memory:`-базу; каждый тест получает её копию (миллисекунды); изоляция полная, включая коммиты |
| Postgres | внутри экземпляра пул размером 1, всё в одной транзакции с откатом в конце теста; вложенные `Repo.transaction` → savepoint'ы |
| Слой | stdlib `Test.isolated(fn -> …)` — тело в новом экземпляре; `Sql` даёт тестовые режимы адаптеров; `Calmar.Test` и `Whelk.Test` — тонкие обёртки. Изоляция доступна и библиотекам, и скриптам |

Следствия:
- экземпляры рантайма (11/M4) — не только для встраивания, но и
  **обязательная** часть тестового стека: поднимаются из S в M;
- симуляционное тестирование (B4) работает внутри экземпляра: seed задаёт
  расписание одного теста, не влияя на соседние.

## 2. Сериализация значений: `Term` (утверждено 2026-09-27)

**Зачем:** персистентная очередь заданий (C5), сессии и кэш, снапшоты
состояния, будущая распределённость. JSON теряет атомы, номинальные записи
и варианты.

| Что | Решение |
|---|---|
| API | `Term.encode(v) -> Result<Bytes, E>`, `Term.decode(bytes, opts) -> Result<Any, E>`; stdlib, Go-native |
| Формат | **CBOR** (RFC 8949) + свои теги: атом, номинальная запись (имя типа + поля **по именам**), вариант, `Decimal`, `Instant`, `Range`, модуль/тип. Pure-Go реализация, без cgo. Версия формата — в заголовке; формат входит в совместимость 1.0 (B5) |
| Не-данные | `Pid`, `Ref`, `Port`, замыкания → `Error((:not_serializable, v))`. Ссылка на именованную `pub fn` модуля кодируется **по имени** (MFA) — это дескриптор для заданий и §13.1 |
| Эволюция записей (§17.4) | **строго + хук**: при декодировании номинальная запись проверяется контрактом (09); не совпало — вызывается `Monitor.upgrade(fields)` (конвенция «модуль типа», L6), если он есть, иначе `Error((:incompatible, type, detail))` |
| Безопасность | по умолчанию **новые атомы не создаются**: неизвестный атом — `Error`; для доверенных источников — явная опция `{ atoms: :create }`. Лимиты глубины и размера. Кода в формате нет, поэтому декодирование не исполняет ничего |

Подписанные и зашифрованные нагрузки (cookie-сессии, токены) —
`Crypto.sign`/`Crypto.seal` поверх `Term.encode`.

## 3. События инструментирования: `Telemetry` (утверждено 2026-09-27)

Один механизм для метрик, OpenTelemetry, логов медленных запросов,
`brig observe` и отчётов о падениях — вместо хуков в каждом пакете.

| Что | Решение |
|---|---|
| Доставка | **синхронно в излучающем акторе** (как `:telemetry`): обработчик — дешёвая функция (обновить счётчик, переслать агрегатору); тяжёлая работа — `send` своему актору. Реестр обработчиков — в `Global` (R13) |
| Цена | при нуле подписчиков излучение — одна проверка в `Global` |
| Ошибка обработчика | обработчик **отключается**, излучается `[:telemetry, :handler, :failed]`, излучающий актор продолжает работу — метрика не роняет запрос |
| Форма | путь из атомов + записи: `Telemetry.emit([:calmar, :request, :stop], { duration_ms: 12 }, { route: …, status: 200 })`; подписка по пути или префиксу; `Telemetry.span(event, meta, fn -> …)` излучает `:start` / `:stop` / `:exception` |
| События VM | в ту же шину: `[:vm, :actor, :down]`, `[:vm, :mailbox, :hwm]`, `[:vm, :resource_limit]` (11/M1), `[:vm, :spawn]`; на них строятся `brig observe` и отчёты о падениях |

Кто излучает из коробки: `Http` (запрос, ответ), `Sql` (запрос, пул),
Calmar (конвейер, действие, рендер), `Server.call`, `Timer`, VM.
Потребители — пакеты: Prometheus-экспорт (`Metrics`), OpenTelemetry (D2),
логгер медленных запросов, `brig observe`.
