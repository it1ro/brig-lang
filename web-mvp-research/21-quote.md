# 21. Основа для `quote`-лямбд (черновик RFC-0001)

**Статус:** основа утверждена 2026-09-27; введение `quote` в язык — отдельным
решением при проектировании пакета `Query` (03/L23), по реальным запросам.
Цель документа — заложить то, что дорого менять потом, и дать RFC готовую
рамку.

## Что утверждено сейчас

| Вопрос | Решение |
|---|---|
| Резерв ключевых слов | `quote` — **зарезервировать сейчас** в §1.3 (семантика — при принятии RFC). Заодно резервируется уже утверждённый `pub` (L3), которого в §1.3 тоже нет. Позднее добавление ключевого слова ломает код, где оно — имя |
| Чистое подмножество | **одно определение для guard'ов и `quote`**, формально в спеке (ниже). Проверяет sema. Как guard'ы в Elixir: без пользовательских функций, I/O и акторных примитивов |
| Формат `Expr` | **вариантный тип stdlib**, независимый от внутреннего AST компилятора; потребитель разбирает его паттерн-матчингом |
| Семантика | **`Expr.eval` — эталон**: `Expr.eval(e, arg)` ≡ вызов обычной лямбды. Любой перевод (SQL, JSON Schema) обязан совпадать с `eval` — проверяется property-тестами |

## Чистое подмножество выражений (для спеки)

Разрешено:
- литералы всех видов, включая `Range`, литералы кортежей, списков,
  записей и мап;
- имена: параметры (функции/лямбды/паттерна) и захваченные переменные;
- доступ к полю `x.field` (L4), индекс `m[k]`;
- операторы: сравнения, арифметика (`+ - * / div rem **`), `and`/`or`/`not`,
  `to`;
- вызовы функций из **белого списка чистых функций stdlib** (помечены в
  документации модуля): `len`, `to_str`, `Map.has_key`, `Map.get_or`,
  `Str.starts_with`, `Str.lower`, `List.member`, `Time.before`, … Список —
  часть спеки, расширяется только через RFC.

Запрещено: вызовы пользовательских функций, `send`/`recv`/`spawn` и другие
акторные примитивы, `raise`/`trap`, I/O, блочные конструкции (`match`,
`with`, `if` с блоками — однострочный `if … then … else …` разрешён).

Следствие для спеки: пример §12.4 `when has_pending(state, id)`
переписывается через белый список: `when Map.has_key(state.pending, id)`.

## Черновик формата `Expr`

```brig module
type Expr {
    Arg(Atom),                   # параметр quote-лямбды
    Captured(Atom, Any),         # захваченная переменная: имя + значение → параметр SQL
    Lit(Any),                    # литерал
    Field(Expr, Atom),           # x.field
    Index(Expr, Expr),           # m[k]
    Op(Atom, Expr, Expr),        # :==, :<, :+, :and, :or, :to, …
    Not(Expr),
    Neg(Expr),
    If(Expr, Expr, Expr),        # однострочный if … then … else …
    Call(Atom, List<Expr>),      # функция из белого списка: :"Str.lower"
    Coll(Atom, List<Expr>),      # литерал коллекции: :list, :tuple, :map, :record
}

type Quoted { params: List<Atom>, body: Expr, source: (Str, Int, Int) }
```

- `quote m -> m.status != :down and m.interval_ms < max` →
  `Quoted{ params: [:m], body: Op(:and, Op(:!=, Field(Arg(:m), :status), Lit(:down)), Op(:<, Field(Arg(:m), :interval_ms), Captured(:max, 60_000))), source: (…) }`.
- `source` — файл и `line:col` для сообщений об ошибках перевода
  («`Str.lower` не поддерживается адаптером SQLite», с указанием места).
- Равенство `Quoted` — структурное; сериализуется `Term` (16), если
  захваченные значения сериализуемы.

## Потребители (зачем это всё)

| Потребитель | Что делает с `Expr` |
|---|---|
| `Query` (14) | переводит в SQL; `Captured` → параметры; неподдерживаемый узел — ошибка с `source` |
| `Check` (09) | правило, экспортируемое в JSON Schema, где выразимо; иначе — описание + рантайм-проверка через `eval` |
| `Test.assert` | «power assert»: при падении печатает значения подвыражений |
| `brig observe`, симуляция (B4) | фильтры событий и акторов |

## Что остаётся решить в RFC

- Синтаксис: `quote m -> …` (одна строка, как стрелка) — достаточно ли; нужна
  ли блочная форма (скорее нет: чистое подмножество не содержит блоков).
- Многопараметрические `quote (a, b) -> …` (L22 делает это естественным).
- Точный белый список функций и порядок его расширения.
- Нужен ли `Expr` как отдельный от `Quoted` публичный тип и стабильность
  набора узлов в рамках совместимости 1.0 (B5).
- Лимиты размера `Expr` и поведение `Term.decode` для чужих `Quoted`.
