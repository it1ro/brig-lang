# 05. Тулчейн, дистрибуция, скриптинг, embedded

## Один бинарник — все команды

Сейчас: `brig run | check | repl | version | help`. Целевой набор:

| Команда | Что делает | Уровень |
|---|---|---|
| `brig run file.brig` / `brig file.brig` | запуск скрипта | есть |
| `brig new NAME` | минимальный проект (библиотека/скрипт) из встроенного шаблона; веб-проекты — `calmar new` (10) | M |
| `brig run --watch` | перезапуск VM при изменении файлов (общий механизм; `calmar server` строится на нём) | M |
| `brig test [path] [--seed N]` | тест-раннер (`Test` уже есть), параллельные акторы, фейковое время | M |
| `brig fmt` | форматтер (AST-форматтер уже есть) | M |
| `brig build [--target os/arch] [-o out]` | self-contained приложение | M |
| `brig console` | REPL с загруженным приложением (как `iex -S mix`) | S |
| `brig fix` | автомиграция исходников при ломающих изменениях 0.x (первая — `fn` → `pub fn`) (B5) | M |
| `brig cert dev` | локальный доверенный сертификат для разработки (как mkcert) (B1) | S |
| `brig test --simulate --seed N` | детерминированное симуляционное тестирование (B4) | S |
| `brig add\|remove\|fetch\|update\|vendor\|why` | зависимости (10) | M |
| `brig install\|uninstall URL` | утилиты из пакетов одним файлом в `~/.local/bin` (10) | M |
| `brig lsp` | language server | S |
| `brig doc` | документация из `@doc` | N |

Всё — подкоманды одного файла. Никаких `brig-lsp`, `brig-fmt` рядом.
Команды фреймворка (`calmar new|server|gen|routes|db`) — у пакета Calmar,
устанавливаемого через `brig install` (10).

## Self-contained сборка приложения

**Формат:** `[копия рантайма brig][payload][трейлер: магия + смещение]`.
Payload — архив: байткод модулей приложения и зависимостей, `priv/`
(статика, миграции), скомпилированные шаблоны, манифест. При старте
рантайм читает свой же файл (`os.Executable()`), находит трейлер и
загружает payload в память — без распаковки на диск.

- Кросс-сборка: `brig build --target linux/arm64` скачивает?.. **нет** —
  нужна копия рантайма под целевую платформу. Варианты: (а) `brig`
  содержит рантаймы всех целей (+×N размера — плохо); (б) рантайм под цель
  тянется один раз и кэшируется (нужна сеть); (в) байткод переносим,
  поэтому `brig build --target X` = «взять `brig` для X» + payload — это
  тот же вариант (б). → Q-cross в 07. Рекомендация: **(б)** с явной
  командой `brig toolchain add linux/arm64` и офлайн-путём «положи бинарник
  сам».
- Байткод версионирован; рантайм отказывается загружать несовместимый
  payload с понятной ошибкой.
- `brig build` = «prod-режим»: stripped, без исходников (опционально с
  исходниками для stack trace с кодом).

## Проект и манифест (§17.5)

Манифест — **модуль на Brig**, а не TOML/YAML (нет второго формата,
парсер уже есть, работает подсветка/fmt):

```brig module
module Project

pub fn project() ->
    {
        name: "lookout",
        version: "0.1.0",
        brig: ">= 0.6",
        deps: [],
    }
```

Ограничение: `project()` — чистая функция без I/O (sema проверяет, что
она состоит из литералов). → Q-manifest в 07.

## Пакетный менеджер — M

Утверждённая архитектура — [10-packages.md](10-packages.md): пакеты —
только Brig-исходники, URL как идентификатор, MVS, одна версия на сборку,
lock с хешами, без install-скриптов, права как в Deno, Chandler — индекс и
кэширующий прокси, `brig add` / `brig install`.

## Серверный скриптинг

Требования и текущий разрыв:

| Требование | Зачем | Статус |
|---|---|---|
| shebang `#!/usr/bin/env brig` | исполняемые скрипты | проверить в лексере (коммент `#` — вероятно уже работает) |
| скрипт без `module Main`/`fn main()`? | однострочники | Q-script в 07 |
| старт < 20 мс | cron, CLI-утилиты | замерить; кэш байткода в `$XDG_CACHE_HOME/brig` по хешу исходника |
| `Sys.args`, `Env`, `Sys.exit(code)` | CLI | частично (T-75) |
| `File`/`Dir`/`Path`, `Proc.run`, stdin построчно | glue-скрипты | нет |
| парсинг аргументов `Cli.parse(spec)` | удобство | S |
| вывод с цветом/таблицами | удобство | N |

Стримы stdin/stdout — тоже порты: `Stdin.lines()` отдаёт сообщения
`(:line, str)`/`(:eof)` актору, что естественно для конвейеров
(`tail -f | brig parse_logs.brig`).

## Embedded / edge

| Требование | Решение |
|---|---|
| кросс-компиляция | Go без cgo: `GOOS/GOARCH` из коробки (arm, arm64, riscv64, mips) |
| малый RSS | замер; `GOGC`/`GOMEMLIMIT` через флаги рантайма; ориентир — работа на 64 МБ RAM |
| периферия | порты `Serial`, `Gpio` (через `/dev`, sysfs/gpiod-chardev без cgo) — N |
| надёжность | супервизия + watchdog-актор; рестарт поддеревьев вместо рестарта процесса |
| обновление | `brig build` → один файл → атомарная замена + рестарт через systemd |

Микроконтроллеры (без MMU/ОС) — вне цели: Go-рантайм их не тянет.

## Стабильность и совместимость (B5)

- **0.x:** ломающие изменения допустимы, но каждое — с автомиграцией
  `brig fix` и записью в CHANGELOG.
- **1.0:** совместимость исходников языка и stdlib в пределах 1.x (в стиле
  Go 1 compatibility promise).
- **Байткод без гарантий:** пакеты распространяются исходниками (10), байткод
  — локальный кэш по ключу «версия компилятора + хеш исходников».
- **Editions** (как в Rust) заранее не вводятся; остаются механизмом на
  случай ломающего изменения после 1.0.
- **Критерий 1.0:** web-MVP (Calmar + Whelk) обкатан на реальных проектах,
  спека закрыта по §17, модель памяти решена по замерам (11).

## WASM (B6)

- **Песочница в браузере** (`brig` → `js/wasm`): учебник и примеры спеки
  запускаются в браузере; без сети и файлов; ~3 МБ gzip. S, вскоре после
  релиза языка.
- **WASI-приложения** (`brig build --target wasip1`): N — в WASI preview1
  нет сокетов, у edge-платформ свои API.

## Встраивание в Go

`pkg/brig` (публичный Go-пакет, отдельно от `internal/`):

```go
rt := brig.New(brig.Options{Reductions: 2000})
rt.RegisterFunc("Host.lookup", func(args []brig.Value) (brig.Value, error) { ... })
mod, err := rt.Compile("rules.brig", src)
res, err := rt.Call(mod, "check", brig.Str("x"))
```

Нужен стабильный `Value`-API и изоляция (несколько независимых рантаймов в
одном процессе). → S, после стабилизации `internal/runtime`.
