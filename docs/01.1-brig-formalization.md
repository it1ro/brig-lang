## A1. `brig.ebnf`

Файл извлекается из §16 v0.4.5. Нормативный источник — §16; этот файл — исполнительный. При расхождении правится §16, потом регенерируется `brig.ebnf`.

```ebnf
(* Brig v0.4.5 — EBNF *)
(* NEWLINE, INDENT, DEDENT, EOF — терминалы, эмитируемые лексером (см. A5). *)
(* Комментарии: # до конца строки; не влияют на offside. *)

(* ============ Программа ============ *)

program      ::= module_decl? import_decl* top_decl*
module_decl  ::= "module" ModuleName NEWLINE
import_decl  ::= "import" ModuleName NEWLINE
alias_decl   ::= "alias" ModuleName "as" ModuleName NEWLINE
ModuleName   ::= UpperIdent ( "." UpperIdent )*
top_decl     ::= fn_decl | type_decl | alias_decl

(* ============ Стейтменты ============ *)

stmt         ::= let_bind | local_fn_decl | expr_stmt
let_bind     ::= pattern "=" expr NEWLINE
expr_stmt    ::= expr NEWLINE
local_fn_decl::= fn_clause+

(* Примечание: let_bind с блочным trap требует NEWLINE после DEDENT блочной формы. *)

(* ============ Функции ============ *)

fn_decl      ::= fn_clause+
fn_clause    ::= "fn" lower_ident "(" [ params ] ")" [ "when" expr ] "->"
                 ( expr NEWLINE | NEWLINE INDENT stmt+ DEDENT )
params       ::= param ( "," param )*
param        ::= pattern | ".." lower_ident

(* ============ Выражения ============ *)

expr         ::= lambda_expr | pipe_expr
lambda_expr  ::= lambda_short | lambda_full
lambda_short ::= lower_ident "->" expr
                 (* Границы expr: до ближайшего токена, не входящего в выражение
                    на этом уровне приоритета: , ) ] } NEWLINE (вне скобок);
                    внутри скобок — до , или закрывающей скобки. См. §4.2 (N2). *)
lambda_full  ::= "fn" "(" [ params ] ")" "->"
                 ( expr NEWLINE | NEWLINE INDENT stmt+ DEDENT )

pipe_expr    ::= range_expr ( "|>" pipe_rhs )*
pipe_rhs     ::= pipe_name [ "(" [ args ] ")" ]
pipe_name    ::= ( lower_ident | UpperIdent )
                 ( "." ( lower_ident | UpperIdent ) )*

range_expr   ::= or_expr [ "to" or_expr ]
or_expr      ::= and_expr ( "or" and_expr )*
and_expr     ::= cmp_expr ( "and" cmp_expr )*
cmp_expr     ::= add_expr [ cmp_op add_expr ]
cmp_op       ::= "==" | "!=" | "<" | ">" | "<=" | ">="
add_expr     ::= mul_expr ( ( "+" | "-" ) mul_expr )*
mul_expr     ::= pow_expr ( ( "*" | "/" | "div" | "rem" ) pow_expr )*
pow_expr     ::= unary_expr [ "**" pow_expr ]
unary_expr   ::= [ "-" | "not" ] postfix_expr
postfix_expr ::= primary_expr postfix_op*
postfix_op   ::= "." ( lower_ident | UpperIdent )
               | "(" [ args ] ")"
               | "[" expr "]"

primary_expr ::= literal
               | lower_ident
               | UpperIdent
               | "(" expr ")"
               | tuple_literal
               | list_literal
               | vector_literal
               | map_literal
               | record_literal
               | if_expr
               | match_expr
               | recv_expr
               | with_expr
               | trap_expr

args         ::= arg ( "," arg )*
arg          ::= expr | ".." expr

(* ============ Литералы ============ *)

literal      ::= int_lit | float_lit | decimal_lit
               | string_lit | bytes_lit | regex_lit
               | atom_lit | bool_lit

atom_lit     ::= ":" lower_ident [ "?" ]
bool_lit     ::= "true" | "false"

tuple_literal  ::= "(" expr "," [ expr ( "," expr )* ] ")"
                   (* (x) — группировка; (x,) — 1-кортеж; (x,y) — n-кортеж *)
list_literal   ::= "[" [ list_elem ( "," list_elem )* [ "," ] ] "]"
vector_literal ::= "%[" [ list_elem ( "," list_elem )* [ "," ] ] "]"
list_elem      ::= expr | ".." expr

map_literal  ::= "%{" [ map_elem ( "," map_elem )* [ "," ] ] "}"
map_elem     ::= expr "=>" expr | ".." expr

record_literal ::= [ TypeName ] "{"
                   [ record_elem ( "," record_elem )* [ "," ] ] "}"
                   (* { ... } в позиции expr — record_literal;
                      в позиции type_body — variant_list/field_list *)
record_elem  ::= lower_ident ":" expr | ".." expr

(* ============ Паттерны ============ *)

pattern      ::= pattern_atom [ "as" lower_ident ]
pattern_atom ::= "_"
               | lower_ident
               | literal
               | constructor_pattern
               | tuple_pattern
               | list_pattern
               | map_pattern
               | record_pattern

constructor_pattern ::= UpperIdent [ "(" [ pattern ( "," pattern )* ] ")" ]
tuple_pattern       ::= "(" pattern "," [ pattern ( "," pattern )* ] ")"
list_pattern        ::= "[" [ pattern ( "," pattern )*
                             [ ".." [ lower_ident ] ] ] "]"
map_pattern         ::= "%{" [ map_pair ( "," map_pair )* ] "}"
map_pair            ::= expr "=>" pattern
record_pattern      ::= TypeName "{"
                        [ field_pattern ( "," field_pattern )* ] "}"
field_pattern       ::= lower_ident ":" pattern

(* ============ Управляющие конструкции ============ *)

if_expr      ::= "if" expr NEWLINE INDENT stmt+ DEDENT
                 [ "else" NEWLINE INDENT stmt+ DEDENT ]
               | "if" expr "then" expr "else" expr

match_expr   ::= "match" expr NEWLINE INDENT match_branch+ DEDENT
match_branch ::= pattern "->"
                 ( expr NEWLINE | NEWLINE INDENT stmt+ DEDENT )

recv_expr    ::= "recv" NEWLINE INDENT recv_branch+ DEDENT
                 [ else_clause ] [ after_clause ]
               | "recv" recv_branch
recv_branch  ::= pattern [ "when" expr ] "->"
                 ( expr NEWLINE | NEWLINE INDENT stmt+ DEDENT )
else_clause  ::= "else" lower_ident NEWLINE INDENT stmt+ DEDENT
                 (* else/after — только блочная форма (INDENT...DEDENT) *)
after_clause ::= "after" expr "->"
                 ( expr NEWLINE | NEWLINE INDENT stmt+ DEDENT )

with_expr    ::= "with" NEWLINE INDENT bind_stmt+ body_stmt+ DEDENT
                 [ "else" NEWLINE INDENT else_branch+ DEDENT ]
bind_stmt    ::= pattern "<-" expr NEWLINE
body_stmt    ::= let_bind | expr NEWLINE
else_branch  ::= pattern "->"
                 ( expr NEWLINE | NEWLINE INDENT stmt+ DEDENT )

trap_expr    ::= "trap" "(" expr ")"
                 (* trap(expr) — синтаксический сахар для trap с единственным
                    body_clause, содержащим стейтмент expr. НЕ вызов функции.
                    См. §8.2. *)
               | "trap" NEWLINE body_clause ( ensure_clause body_clause? )*
body_clause  ::= INDENT stmt+ DEDENT
ensure_clause::= "ensure" ( expr NEWLINE | NEWLINE INDENT stmt+ DEDENT )

(* trap_expr в primary_expr: грамматически допускается в любой позиции,
   но семантически разрешён только как RHS let_bind или expr_stmt.
   Контекстная проверка выдаёт ошибку при нарушении. См. §16.10. *)

(* ============ Типы ============ *)

type_decl     ::= "type" TypeName [ "<" GenericParams ">" ] type_body
GenericParams ::= TypeVar ( "," TypeVar )*
type_body     ::= "{" variant_list "}"
                | "{" field_list "}"
                | "=" type_expr

variant_list  ::= variant ( "," variant )*
variant       ::= ConName [ "(" type_expr ( "," type_expr )* ")" ]
field_list    ::= field ( "," field )*
field         ::= lower_ident ":" type_expr

type_expr     ::= TypeName [ "<" type_expr ( "," type_expr )* ">" ]
                | TypeVar
                | "()"
                | "(" type_expr ( "," type_expr )* ")"
                | "(" [ type_expr ( "," type_expr )* ] ")" "->" type_expr
                (* (Int) — группировка типа; (Int,) — 1-кортеж типа *)

(* ============ Лексические терминалы ============ *)

lower_ident  ::= [a-z] [a-zA-Z0-9_]*
UpperIdent   ::= [A-Z] [a-zA-Z0-9_]*
TypeName     ::= UpperIdent
ConName      ::= UpperIdent
TypeVar      ::= UpperIdent

int_lit      ::= "0x" hex_digit ( hex_digit | "_" )*
               | "0b" bin_digit ( bin_digit | "_" )*
               | "0o" oct_digit ( oct_digit | "_" )*
               | dec_digit ( dec_digit | "_" )*

float_lit    ::= dec_digit ( dec_digit | "_" )* "."
                 dec_digit ( dec_digit | "_" )* [ exponent ]
               | dec_digit ( dec_digit | "_" )* exponent
exponent     ::= ( "e" | "E" ) [ "+" | "-" ] dec_digit ( dec_digit )*

decimal_lit  ::= "dec" "\"" decimal_body "\""
string_lit   ::= "\"" ( string_char | interpolation )* "\""
bytes_lit    ::= "b\"" ( bytes_char )* "\""
regex_lit    ::= "rx\"" ( regex_char )* "\""
                 (* regex_lit: статус Should (feature-flagged).
                    Если фича не реализована — парсер выдаёт
                    "feature not implemented". *)

interpolation::= "\\(" expr ")"

(* Правила string_char, bytes_char, regex_char, decimal_body — см. A4. *)
```

````

Замечания:

- `NEWLINE`, `INDENT`, `DEDENT` — терминалы, эмитируемые лексером (A5). Внутри `(...)`, `[...]`, `{...}`, `%[...]`, `%{...}` они не эмитируются.
- `pipe_rhs` определён явно через `pipe_name` — КР-001.
- `bool_lit` — `true`/`false`.
- `atom_lit` — `:` + `lower_ident` + опциональный `?`.
- `_` — wildcard-терминал, только в паттернах.
- `..` — терминал, не оператор.
- `interpolation` — только внутри `string_lit`, не внутри `bytes_lit`.
- Одиночный `%` без `[`/`{` — ошибка лексера (КР-005).

## A2. Спецификация скрипта проверки примеров

**Цель.** Прогнать все `brig`-примеры из документа v0.4.5 через парсер и убедиться, что они парсятся без ошибок. Реализует принцип #10.

**Имя:** `tools/check-examples`.

**Вход.**

- Markdown-файл(ы) с дизайном (например, `01-language-design.md`).
- `brig.ebnf` — для генерации или валидации парсера.

**Извлечение примеров.**

- Все fenced-блоки с языком `brig` считаются примерами.
- Каждый блок имеет **режим**, определяемый по метаданным fence:
  - ` ```brig module ` — тело модуля: только `module`/`import`/`alias`/`type`/`fn`.
  - ` ```brig repl ` — REPL: разрешены top-level `let` и выражения, строки могут начинаться с `>`.
  - ` ```brig expr ` — одиночное выражение; оборачивается в `fn main() -> <expr>`.
  - ` ```brig stmt ` — последовательность стейтментов; оборачивается в `fn main() -> ...`.
  - ` ```brig ` (без метки) — эвристика: если есть `module`/`import`/`fn main` → `module`; если есть `>` → `repl`; если одна строка без `=` → `expr`; иначе → `stmt`.
- Если блок в v0.4.5 не имеет метки и эвристика неоднозначна — скрипт **выдаёт предупреждение** и требует явной метки.

**Обработка.**

- Для `module`: парсить как `program`.
- Для `repl`: парсить каждую строку как отдельный top-level стейтмент; `>` — приглашение, отбрасывается; вывод (`6`, `11`) — отбрасывается по эвристике (строки без `=`, без оператора, не начинающиеся с ключевого слова).
- Для `expr`/`stmt`: обернуть в `fn main() -> ...` и парсить как `program`.

**Выход.**

- Exit code 0 — все примеры распарсились.
- Exit code 1 — хотя бы один пример не распарсился.
- Отчёт: `file:line:col — status — [error message]`.

**Проверки помимо парсинга (семантические ограничения на уровне скрипта).**

- Никаких `trap` в позиции аргумента или элемента литерала (N4, КР-003).
- Никаких `Result[...]` в позиции типа (B4).
- Никаких `fn -> ...` (B2).
- Никаких `Ok(x) ≡ (:ok, x)` в семантических примерах — только в комментариях.
- Никаких `f(..)` без операнда в args (М-004).

**Реализация.**

- Парсер — из `brig.ebnf` (tree-sitter, ANTLR или рукописный рекурсивный спуск).
- На первом этапе — рукописный парсер-заглушка, проверяющий только структуру (offside + скобки + ключевые слова).
- На втором — полноценный парсер.

**CI.**

- Запуск на каждый коммит в `01-language-design.md`.
- Кэш: если `brig.ebnf` и `01-language-design.md` не менялись — пропустить.

## A3. Спецификация токенов

### A3.1 Полный список токенов

**Ключевые слова (зарезервированы):**

```
fn match recv with else if then after when alias import module type ensure trap
and or not div rem to true false as
```

**Идентификаторы:**

- `LOWER_IDENT` — `[a-z][a-zA-Z0-9_]*` + опциональный `?` в конце. Примеры: `x`, `foo`, `and?`, `map`, `_x` (запрещён: начинается с `_`).
- `UPPER_IDENT` — `[A-Z][a-zA-Z0-9_]*`. Примеры: `User`, `Http`, `Client`, `Map`.
- `WILDCARD` — `_`. Только в позиции `pattern`.

**Атомы:**

- `ATOM` — `:` + `LOWER_IDENT`. Примеры: `:ok`, `:none`, `:not_found`, `:and?`.

**Числа:**

- `INT` — `0x...`, `0b...`, `0o...`, десятичные с `_`.
- `FLOAT` — десятичные с `.` или экспонентой.
- `DECIMAL` — `dec"..."`.

**Строки и байты:**

- `STRING` — `"..."` с интерполяцией и escape.
- `BYTES` — `b"..."` с escape, без интерполяции.
- `REGEX` — `rx"..."`.

**Операторы (длинные → короткие):**

```
|>  **  ==  !=  <=  >=  ..  ->  <-  =>
+  -  *  /  <  >  =  .
```

**Разделители:**

```
(  )  [  ]  {  }  %[  %{  ,  :  ;
```

**Offside-терминалы:**

- `NEWLINE` — конец логической строки.
- `INDENT` — вход в блок.
- `DEDENT` — выход из блока.
- `EOF` — конец файла.

**Комментарии:**

- `#` до конца строки. Не эмитируется как токен; отбрасывается лексером.

### A3.2 Порядок распознавания

На каждом шаге лексер:

1. Пропускает горизонтальные пробелы (кроме случая line-start — см. A5).
2. Если `#` — пропускает до конца строки.
3. Если `"` — читает `STRING`.
4. Если `b"` — читает `BYTES`.
5. Если `rx"` — читает `REGEX`.
6. Если `dec"` — читает `DECIMAL`.
7. ⚠ Если текущий символ `:` и следующий символ — `[a-z]` или `_` — читает `ATOM` (`:lower_ident[?]`).
   **Иначе** `:` — токен-разделитель `COLON`.
   - Последствия: `::` → два токена `COLON` `COLON`.
   - `:` перед `UpperIdent` (например, `%{ :K => 1 }`) → `COLON` + `UPPER_IDENT`.
   - `:` перед цифрой → `COLON` + `INT` (разделитель валиден).
   - Атом всегда требует `lower_ident` после `:` (согласовано с §1: атом не может начинаться с `_` или `PascalCase`).
8. Если `0x`/`0b`/`0o` — читает `INT`.
9. Если цифра — читает `INT` или `FLOAT` (по наличию `.` или `e`/`E`).
10. Если `[A-Z]` — читает `UPPER_IDENT`.
11. Если `[a-z]` или `_` — читает `LOWER_IDENT` или `WILDCARD` (до `?` в конце, если есть).
    **11a.** ⚠ Для прочитанной лексемы `LOWER_IDENT`/`WILDCARD`:
    - Если лексема **без финального `?`** входит в список зарезервированных слов (A3.1) — эмитировать `KEYWORD`.
    - Иначе — эмитировать `LOWER_IDENT` (включая случаи с финальным `?`, например `and?`, `map?`) или `WILDCARD` (только для `_`).
12. Если символ — начало оператора/разделителя — читает самый длинный подходящий.
13. Иначе — ошибка лексера с `line:col`.

### A3.3 Особые случаи

- `..` — один токен, не два `.`.
- `%[` и `%{` — один токен каждый, не `%` + `[`.
- ⚠ **Одиночный символ `%`, не за которым сразу следует `[` или `{`, является ошибкой лексера (`line:col`).** Оператора `%` в языке нет.
- `..args` — токен `..` + `LOWER_IDENT`, не слитно.
- `x?` — `LOWER_IDENT` с `?` в конце. `x ? y` — три токена (но `?` не оператор → ошибка парсинга).
- `and?` — `LOWER_IDENT`, не keyword `and` + `?` (правило 11a).
- `:` в `ATOM` требует, чтобы следующий символ был `[a-z]` или `_`; иначе `:` — разделитель (в `let_bind`, `field`, `key: value`). См. шаг 7 A3.2.
- `::` — два токена `COLON` `COLON` (см. шаг 7 A3.2).
- `-1` — токен `-` (унарный) + `INT`, не часть литерала.
- `1e9` — `FLOAT`. `1e` — ошибка. `1.e9` — ошибка.
- `0x` без цифр — ошибка.
- `1__0` — ошибка (двойной `_`).
- `1_` — ошибка (`_` в конце).
- `_1` — ошибка (`_` в начале, не wildcard).
- `_` — `WILDCARD`.

### A3.4 Ключевые слова как атомы

Зарезервированные слова **не могут** быть `LOWER_IDENT`. Но атомы с ними — разрешены:

- `:if`, `:and`, `:else`, `:then`, `:when`, `:fn`, `:to`, `:after` — валидные атомы.
- `if`, `and`, `else` — keywords, не идентификаторы.
- `:and?` — валидный атом (с `?`).

### A3.5 Ключевые слова как модули/типы

Зарезервированные слова **не могут** быть `UPPER_IDENT`. Поэтому `type If { ... }` — ошибка. Но `type Atom { ... }` — OK, потому что `Atom` не keyword.

## A4. Escape-последовательности (закрывает §15.1)

### A4.1 `Str` (`"..."`)

| Escape      | Значение            | Кодпоинт     |
| ----------- | ------------------- | ------------ |
| `\n`        | новая строка        | U+000A       |
| `\t`        | таб                 | U+0009       |
| `\r`        | возврат каретки     | U+000D       |
| `\0`        | NUL                 | U+0000       |
| `\\`        | обратный слэш       | U+005C       |
| `\"`        | двойная кавычка     | U+0022       |
| `\(`        | начало интерполяции | —            |
| `\u{H...H}` | unicode codepoint   | 1–6 hex-цифр |
| другой `\X` | ошибка лексера      | —            |

Правила:

- `\u{...}` — 1–6 hex-цифр, значение ≤ U+10FFFF, не в диапазоне surrogate (U+D800–U+DFFF).
  **⚠ Проверка диапазона и синтаксиса выполняется в лексере.** При нарушении — ошибка лексера с `line:col`. Поведения:
  - `\u{}` (пусто) — ошибка лексера.
  - `\u{110000}` (> U+10FFFF) — ошибка лексера.
  - `\u{D800}` (surrogate) — ошибка лексера.
- `\(...)` — границы до соответствующей `)` с учётом вложенности `()`, `[]`, `{}` и вложенных строк. Внутри — любое выражение.
- **⚠ Незакрытая интерполяция:** если `\(` не имеет соответствующей `)` до конца строки или до закрывающей кавычки строки — ошибка **лексера** с указанием позиции открывающего `\`.
- Строка должна быть валидной UTF-8. Некорректные байты в исходнике — ошибка лексера.
- `\xHH` в `Str` **запрещён**: байты без UTF-8 — только в `Bytes`.
- Многострочный литерал `"""..."""` — если реализован, поддерживает те же escape плюс literal newlines. **(should have)**

### A4.2 `Bytes` (`b"..."`)

| Escape      | Значение        | Байт                |
| ----------- | --------------- | ------------------- |
| `\n`        | новая строка    | 0x0A                |
| `\t`        | таб             | 0x09                |
| `\r`        | возврат каретки | 0x0D                |
| `\0`        | NUL             | 0x00                |
| `\\`        | обратный слэш   | 0x5C                |
| `\"`        | двойная кавычка | 0x22                |
| `\xHH`      | байт            | 1 байт, 2 hex-цифры |
| другой `\X` | ошибка лексера  | —                   |

Правила:

- `\(` **запрещён** в `Bytes`: интерполяции нет.
- `\u{...}` **запрещён** в `Bytes`: байты без Unicode-семантики.
- Любой байт 0x00–0xFF допустим.
- `Bytes.to_str(b)` при невалидной UTF-8 → `raise((:invalid_utf8, b))`.

### A4.3 `Regex` (`rx"..."`)

| Escape      | Значение                                    |
| ----------- | ------------------------------------------- |
| `\"`        | литерал `"`                                 |
| `\\`        | литерал `\`                                 |
| другой `\X` | сохраняется как `\X` (для regex-синтаксиса) |

Правила:

- Тело — регулярное выражение, синтаксис — stdlib-специфичен.
- Интерполяции нет.
- Многострочность: зависит от флагов regex, не от литерала.

### A4.4 `Decimal` (`dec"..."`)

| Символ    | Значение                                 |
| --------- | ---------------------------------------- |
| `0`–`9`   | цифра                                    |
| `_`       | разделитель (между цифрами)              |
| `.`       | десятичная точка (опционально, один раз) |
| `+` / `-` | знак (только в начале)                   |

Правила:

- Формат: `[+-]? [0-9_]+ ( "." [0-9_]+ )?`.
- `_` только между цифрами.
- Без экспоненты: `dec"1e9"` — ошибка.
- `dec".5"` — ошибка.
- `dec"1."` — ошибка.
- Точность — произвольная; рантайм решает.

⚠ **Валидные формы (примеры):**

- `dec"1_000.5"` — валидно.
- `dec"-1.5"` — валидно (знак в начале).
- `dec"+1"` — валидно.
- `dec"1.50"` — валидно.

⚠ **Невалидные формы (примеры):**

- `dec"1e9"` — ошибка (экспонента запрещена).
- `dec".5"` — ошибка (нет ведущей цифры).
- `dec"1."` — ошибка (нет цифры после точки).
- `dec"1__0"` — ошибка (двойной `_`).

### A4.5 Некорректная UTF-8

| Ситуация                               | Поведение                      |
| -------------------------------------- | ------------------------------ |
| Некорректная UTF-8 в исходнике `Str`   | ошибка лексера, `line:col`     |
| Некорректная UTF-8 в `Bytes`           | допустима (байты)              |
| `Bytes.to_str(b)` при невалидной UTF-8 | `raise((:invalid_utf8, b))`    |
| `Str.to_bytes(s)`                      | всегда успешно, UTF-8-байты    |
| `Str` в JSON                           | сериализуется как UTF-8-строка |

## A5. Псевдокод offside-алгоритма

### A5.1 Состояние лексера

```
indent_stack : [0]          # стек отступов, начинается с 0
paren_depth  : 0            # глубина вложенности в () [] {} %[] %{}
stmt_indent  : 0            # отступ первой строки текущего стейтмента
first_line   : true         # первая ли строка файла
in_string    : false        # внутри Str/Bytes/Regex (для пропуска newlines)
```

### A5.2 Основной цикл

```
for each physical_line:
    if in_string:
        continue lexing string  # строки могут содержать newlines

    if is_blank(physical_line) or is_comment_only(physical_line):
        continue  # не влияет на offside

    if paren_depth > 0:
        # внутри скобок — offside отключён
        lex_tokens(physical_line)   # без NEWLINE, без INDENT/DEDENT
        update_paren_depth()
        continue

    indent = count_leading_spaces(physical_line)
    first_tok = peek_first_token(physical_line)

    if first_tok in CONTINUATION_OPS:
        # строка-продолжение
        if indent <= stmt_indent:
            error("continuation must be indented more than statement")
        lex_tokens(physical_line)   # без NEWLINE, без INDENT/DEDENT
        update_paren_depth()
        # ⚠ stmt_indent НЕ изменяется — он фиксирует отступ ПЕРВОЙ строки
        # логического стейтмента (см. СУ-004).
        continue

    # новая логическая строка
    if not first_line:
        emit NEWLINE

    # закрыть/открыть блоки
    if indent > indent_stack.top():
        indent_stack.push(indent)
        emit INDENT
    elif indent < indent_stack.top():
        while indent_stack.top() > indent:
            indent_stack.pop()
            emit DEDENT
        if indent_stack.top() != indent:
            error("inconsistent dedent")
    # indent == top: ничего не эмитим (NEWLINE уже был)

    stmt_indent = indent
    first_line  = false
    lex_tokens(physical_line)
    update_paren_depth()

# EOF
while indent_stack.top() > 0:
    indent_stack.pop()
    emit DEDENT
emit EOF
```

### A5.3 Множество `CONTINUATION_OPS`

```
|>  and  or  +  -  *  /  **  div  rem  to
==  !=  <  >  <=  >=  ..
```

Правило: если первый токен строки — один из этих операторов, строка считается продолжением предыдущей логической строки. `NEWLINE` перед ней не эмитится, `INDENT`/`DEDENT` не эмитятся, отступ должен быть строго больше отступа первой строки стейтмента.

### A5.4 Взаимодействие с бракетными литералами

- `paren_depth` инкрементируется на `(`, `[`, `{`, `%[`, `%{`.
- Декрементируется на `)`, `]`, `}`.
- Пока `paren_depth > 0`, offside-токены не эмитируются; newlines внутри скобок — whitespace.
- Offside-блоки **внутри** скобок (например, `fn` внутри `%{...}`) работают по тому же алгоритму, но с якорем на токене `fn`, а не на открывающей скобке. Это реализуется тем, что при виде `fn`/`match`/`recv`/`with`/`trap`/`if` внутри скобок лексер запоминает текущий `paren_depth` и **временно включает offside-режим** до возврата на тот же `paren_depth`. Практически: offside-блок — отдельный мини-проход, изолированный от внешних скобок.

Формально (синхронизировано с §1.36 — СУ-003):

```
lex_offside_block(opener):
    saved_depth = paren_depth
    saved_stack = indent_stack
    # opener — токен fn/match/recv/with/trap/if
    # ⚠ base_indent = колонка (отступ) токена opener в физической строке.
    # Именно этот отступ становится базовым для блока (СУ-003).
    base_indent = column_of(opener)
    indent_stack = [base_indent]
    paren_depth = 0
    ... lex block ...
    indent_stack = saved_stack
    paren_depth = saved_depth
```

Это даёт одинаковое поведение для `fn` на верхнем уровне и `fn` внутри `%{...}`. **Якорь offside-блока всегда = колонка токена-открывателя в физической строке.**

### A5.5 Пример

```brig
fn main() ->
    x = 1
    y = 2
    x + y
```

Токены:

```
fn  LOWER_IDENT(main)  (  )  ->  NEWLINE  INDENT
LOWER_IDENT(x)  =  INT(1)  NEWLINE
LOWER_IDENT(y)  =  INT(2)  NEWLINE
LOWER_IDENT(x)  +  LOWER_IDENT(y)  NEWLINE  DEDENT  EOF
```

### A5.6 Пример с продолжением

```brig
fn main() ->
    x = 1
        + 2
    x
```

Токены:

```
fn  LOWER_IDENT(main)  (  )  ->  NEWLINE  INDENT
LOWER_IDENT(x)  =  INT(1)  +  INT(2)  NEWLINE
LOWER_IDENT(x)  NEWLINE  DEDENT  EOF
```

`+ 2` — continuation (первый токен `+`), отступ `8 > 4`, NEWLINE перед ним не эмитится, INDENT/DEDENT не эмитятся. **`stmt_indent` остаётся равным `4` (отступу `x = 1`) — не изменяется при обработке continuation-строки** (СУ-004).

## A6. Расхождения в §16 v0.4.5 и предложения

Найдены при извлечении `brig.ebnf`. Все критические расхождения закрыты в v0.4.5.

### A6.1 `call_expr` не определён — **ЗАКРЫТО (КР-001)**

**Проблема (в v0.4.4).** §16.4: `pipe_rhs ::= call_expr`. `call_expr` нигде не определён.

**Решение (применено в v0.4.5).** Заменено на явное определение:

```
pipe_rhs  ::= pipe_name [ "(" [ args ] ")" ]
pipe_name ::= ( lower_ident | UpperIdent ) ( "." ( lower_ident | UpperIdent ) )*
```

Синхронизировано между §16.4 и `brig.ebnf` (A1).

### A6.2 `trap(expr)` — семантика — **ЗАКРЫТО (КР-002)**

**Проблема (в v0.4.4).** §16.7: `trap_expr ::= "trap" "(" expr ")" | ...`. Неясно, что означает `trap(expr)`.

**Решение (применено в v0.4.5).** Вариант (а): `trap(expr)` — синтаксический сахар для блочной формы с единственным `body_clause`, содержащим стейтмент `expr`. Чисто синтаксический сахар, не вызов функции. Явно зафиксировано в §8.2 и A1.

### A6.3 `record_literal ::= [TypeName] "{" ... "}"`

**Статус.** Оставлено как есть. `{ ... }` в позиции `expr` — `record_literal`; в позиции `type_body` — `variant_list`/`field_list` (различие по контексту). Добавлен комментарий в A1 и §16.5.

### A6.4 `primary_expr` включает `trap_expr` — **ЗАКРЫТО (КР-003)**

**Проблема (в v0.4.4).** §16.4 разрешает `trap` в любой позиции. §16.10 запрещает в `args` и литералах.

**Решение (применено в v0.4.5).** Запрет — **контекстный (семантический)**, не грамматический. Парсер допускает `trap_expr` в `primary_expr`, дальнейший этап (семантический анализ) выдаёт ошибку при нарушении. Добавлено явное указание в §16.10 и A1.

### A6.5 `(x)` группировка vs 1-кортеж

**Статус.** Оставлено. В §16.5 и A1 добавлен комментарий: `(x)` — группировка; `(x,)` — 1-кортеж; `(x,y)` — n-кортеж.

### A6.6 вариант без аргументов

**Статус.** Оставлено. Согласовано с N1 (конструктор без аргументов — значение).

### A6.7 `(Int)` группировка типа

**Статус.** Зафиксировано в §16.8 и A1: `(Int)` — группировка типа; `(Int,)` — 1-кортеж типа.

### A6.8 `float_lit` и `1e9`

**Статус.** Оставлено. `1e9` — `Float`; `1` — `Int`. Добавлено в §2.1.

### A6.9 `regex_lit` — статус — **ЗАКРЫТО (Р-008)**

**Проблема (в v0.4.4).** `regex_lit` в `brig.ebnf` (A1), но в §16.5 отсутствовал.

**Решение (применено в v0.4.5).** Держим `regex_lit` в грамматике как feature-flagged (Should). Добавлен в §16.5 и §16.9. Парсер при недоступной фиче выдаёт «feature not implemented» (не ошибку парсинга).

### A6.10 `decimal_lit` — статус

**Статус.** Держим в грамматике как feature-flagged (Should). Поведение аналогично A6.9.

### A6.11 Новое: `lambda_short` границы — **ЗАКРЫТО (СУ-001)**

**Проблема.** `lambda_short ::= lower_ident "->" expr` не выражает границы тела.

**Решение.** Добавлен комментарий в §16.4 и A1: границы `expr` определяются лексическим/синтаксическим правилом привязки (до `,`, `)`, `]`, `}`, `NEWLINE` вне скобок; до `,`/закрывающей скобки внутри).
