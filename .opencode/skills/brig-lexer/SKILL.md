# Лексер Brig

Пакет `internal/lexer/`. **Исполнительная спецификация — A3/A4/A5** в
`01.1-brig-formalization.md`. Нормативные источники дизайна: §1 (синтаксис),
§2.1–2.2 (литералы), §5.0 (приоритеты), §16 (грамматика). Этот скилл
описывает инварианты и грабли пакета, а не дублирует A3/A4/A5.

## Когда применять / не применять

**Применять:** правки `token.go`, `lexer.go`, `escape.go`, `lexer_test.go`,
добавление токенов, offside-логика, escape-валидация, lexer-ошибки.

**Не применять:** парсер, AST, VM, CLI — для них свои скиллы
(`brig-ast`, `brig-cli`, ...). Лексер отдаёт токены и позиции; как их
потребляет парсер — не его забота.

## Инварианты

Это критично. Ломать нельзя без обновления спецификации.

1. **Порядок распознавания на каждом шаге — фиксирован (A3.2).**
   Нарушение порядка = другой токен на выходе. Порядок ниже.
2. **`stmt_indent` фиксирует отступ ПЕРВОЙ строки стейтмента** и **не
   меняется** на continuation-строках (СУ-004). Это инвариант, не эвристика.
3. **Якорь offside-блока — колонка токена-открывателя**
   (`fn`/`match`/`recv`/`with`/`trap`/`if`) в физической строке, не отступ
   строки с открывающей скобкой (СУ-003).
4. **Внутри скобок (`paren_depth > 0`) offside отключён** — newlines
   становятся whitespace. Работает мини-проход `lex_offside_block` (A5.4).
5. **Пустые строки и строки-комментарии не влияют на offside.**
6. **Валидация escape — в лексере, не в парсере (П-002).** Некорректный
   escape должен упасть на этапе токенизации, с позицией.
7. **Позиция ошибки — точная.** Для незакрытой `\(` — позиция открывающего
   `\` (П-003), не конца файла.
8. **Некорректная UTF-8 в Str — ошибка лексера (A4.5).** Не «заменить на
   U+FFFD и продолжить».

## Порядок распознавания (A3.2)

Строго по порядку, на каждом шаге:

1. Горизонтальные пробелы (кроме line-start — см. A5).
2. `#` → комментарий до конца строки (не эмитится).
3. `"` → STRING; `b"` → BYTES; `rx"` → REGEX; `dec"` → DECIMAL.
4. `:` + `[a-z]`/`_` → ATOM (`:lower_ident[?]`); **иначе** `:` → COLON.
5. `0x`/`0b`/`0o` → INT; цифра → INT или FLOAT.
6. `[A-Z]` → UPPER_IDENT.
7. `[a-z]`/`_` → LOWER_IDENT или WILDCARD.
8. **11a (КР-004):** лексема без финального `?`, входящая в зарезервированные,
   → KEYWORD; иначе LOWER_IDENT (включая `and?`, `map?`) или WILDCARD.
9. Операторы — **самый длинный подходящий**: `|>  **  ==  !=  <=  >=  ..  ->  <-  =>`.
10. Иначе — ошибка лексера с `line:col`.

**Особые случаи (A3.3):**

- `..` — один токен.
- `%[` и `%{` — один токен; одиночный `%` — **ошибка лексера (КР-005)**.
- `-1` — `-` + INT.
- `1e9` → FLOAT; `1e` — ошибка.
- `1__0`, `1_`, `_1` — ошибки.
- `_` — WILDCARD.

## Offside (A5)

Состояние: `indent_stack=[0]`, `paren_depth=0`, `stmt_indent=0`,
`first_line=true`.

- **Continuation:** первый токен строки из `CONTINUATION_OPS`
  (`|> and or + - * / ** div rem to == != < > <= >= ..`) → строка-продолжение;
  отступ строго больше `stmt_indent`. **`stmt_indent` при этом не меняется**
  (СУ-004).
- **INDENT/DEDENT** — по сравнению с `indent_stack.top()`; несостыковка
  dedent → `error("inconsistent dedent")`.
- **Якорь** — `base_indent = column_of(opener)` (СУ-003).

## Escape (A4)

| Контекст | Разрешено                                                                | Запрещено                                                         |
| -------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| Str      | `\n \t \r \0 \\ \" \(` + `\u{H...H}` (1–6 hex, ≤ U+10FFFF, не surrogate) | `\xHH`, `\u{D800–DFFF}`, `\u{>10FFFF}`                            |
| Bytes    | `\n \t \r \0 \\ \" \xHH`                                                 | `\(`, `\u{}`                                                      |
| Regex    | `\"`, `\\` — литералы; остальное `\X` сохраняется                        | —                                                                 |
| Decimal  | `[+-]? [0-9_]+ ("." [0-9_]+)?`; `_` только между цифрами                 | экспонента; `dec".5"`, `dec"1."`, `dec"1e9"`, `dec"1__0"` (П-004) |

- Незакрытая интерполяция `\(` без парной `)` — **ошибка лексера** с
  позицией открывающего `\` (П-003).

## Пример: правило offside, которое ломают чаще всего

```go
// lexer.go — упрощённо
func (l *Lexer) handleLineStart() {
    if l.parenDepth > 0 {
        l.skipWhitespace() // offside отключён внутри скобок
        return
    }
    indent := l.countIndent() // в колонках, не в табах «на глаз»

    if l.isContinuationLine() {
        // stmtIndent НЕ трогаем (СУ-004) — иначе многострочный стейтмент
        // получит новый offside-блок
        return
    }

    switch cmp(indent, l.indentStack.top()) {
    case equal:   // та же логическая строка
    case greater: l.emit(INDENT); l.indentStack.push(indent)
    case less:    l.dedentTo(indent) // несостыковка → error("inconsistent dedent")
    }
}
```

При правке offside **обязательно** проверять:

1. Многострочный `fn` с телом на большем отступе — INDENT/DEDENT парные.
2. Continuation-строка (`x = 1` \n `  |> f`) — `stmt_indent` не сдвинулся.
3. `f(\n  1,\n  2\n)` — внутри скобок offside отключён, INDENT не эмитится.
4. `%{ :K => fn() { ... } }` — якорь от `fn`, не от `{` (СУ-003).

параллельных обходах (`check-examples` запускает несколько файлов).

## Частые ошибки

- **Упущен шаг 11a** — `and?` токенизируется как KEYWORD + `?`. Симптом:
  парсер видит `KEYWORD("and")` там, где ожидался идентификатор.
- **`:` перед UpperIdent (`%{ :K => 1 }`) отдан как ATOM** — должно быть
  COLON. Симптом: парсер map-литерала падает на `:K`.
- **Continuation меняет `stmt_indent`** — ломает многострочные стейтменты.
  Симптом: `x = 1` \n `  |> f` \n `y = 2` — `y` уезжает в continuation.
- **Offside-блок внутри `%{...}` берёт якорь от скобки, а не от `fn`**
  (СУ-003). Симптом: INDENT/DEDENT эмитятся на неверных колонках, парсер
  падает на вложенных лямбдах.
- **`\u{110000}` пропущен без проверки** — лексер обязан падать.
  Симптом: парсер получает невалидный кодпоинт и падает в непонятном месте.
- **Некорректная UTF-8 заменяется на U+FFFD** — должно быть ошибкой (A4.5).
  Симптом: тест на invalid UTF-8 «проходит», а на выходе — не тот
  токен, что ожидалось.
- **Позиция незакрытой `\(` указывает на конец файла** — должно быть
  на открывающий `\` (П-003). Симптом: диагностика бесполезна для
  пользователя, тест на позицию падает.
- **Порядок распознавания переставлен** (например, операторы раньше
  идентификаторов) — `to` парсится как оператор в контексте, где ожидался
  идентификатор. Симптом: ломается `to` как имя функции.
