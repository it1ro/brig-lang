# CLI и REPL Brig

Бинарь `brig` — референсный интерпретатор. Go-модуль
`github.com/itiro/brig-lang`. **Источник истины по REPL — §10.7**, по точке
входа `run` — §9, по `check-examples` — A2. Этот скилл описывает инварианты,
форматы вывода и грабли, а не дублирует спецификацию.

## Когда применять / не применять

**Применять:** правки `cmd/brig/*`, `cmd/check-examples/*`, поведение REPL,
форматы диагностик, exit codes, авто-raise-сообщения, прелюдии `print`/`eprint`/`log`.

**Не применять:** изменение лексера/парсера/VM/типов — для этого свои скиллы
(`brig-ast`, `brig-lexer`, `brig-vm`, ...). Здесь CLI — только потребитель их API.

## Карта команд

```

brig run <file.brig> # выполнить модуль: Main + fn main() (§9)
brig check <file.brig> # распарсить + проверить, не исполняя
brig fmt <file.brig> # парс → AST → канонический вывод (идемпотентно)
brig repl # интерактивный режим (§10.7)
brig help / brig version

```

`brig check` использует те же правила, что `tools/check-examples` (A2), но
на одном файле. Exit 0 — успех парсинга и семантической проверки.

## Инварианты CLI и REPL

Это критично. Ломать нельзя без обновления спецификации.

1. **Точка входа `run` — `module Main` + `fn main()` (§9).** Файл без
   `fn main()` — ошибка, не «ничего не делать».
2. **REPL: каждая строка — новая top-level область (принцип #12).**
   Имя связывается один раз в лексической области; в REPL каждая строка —
   новая область.
3. **REPL: замыкания — лексический снимок (N12).** Замыкание захватывает
   связывание своей строки. Позднее `x = 10` в следующей строке не влияет
   на ранее созданное замыкание. Реализация: захваченные REPL-переменные
   **копируются по значению**, а не по имени.
4. **Exit codes фиксированы:**
    - `0` — ok
    - `1` — ошибка парсинга / семантической проверки
    - `2` — runtime uncaught raise
    - `3` — внутренняя ошибка (panic, I/O)
      Не путать 1 и 2 — это частая ошибка.
5. **Формат диагностик единый:** `file:line:col — <message>`.
   Для runtime — `raised (:function_clause, args)` + стек-подсказка;
   тексты авто-raise берутся из фиксированного списка §8.3, не сочиняются.
6. **`fmt` идемпотентен:** `fmt(fmt(x)) == fmt(x)`. Это проверяется в тестах.
7. **`print` / `eprint` / `log`** — прелюдии (§9.1):
    - `print` → stdout
    - `eprint` → stderr
    - `log` → со временем; **поток зафиксирован в одном месте**
      (`internal/prelude/io.go`) — не разбрасывать выбор stdout/stderr по коду.

## REPL: мультистрочка

Правило: лексер накапливает логические строки. Продолжение запрашивается,
если в конце строки есть незакрытое:

- незакрытая `\(` или интерполяция;
- открытая `(` / `[` / `{`;
- ожидание INDENT-тела после `fn`, `match`, `recv`, `with`, `trap`, `if`;
- `->` без тела.

**Реализацию подчинять offside-правилам A5**, а не «склейке строк». Если
правило продолжения расходится с A5 — прав A5, а не эвристика REPL.

## Формат вывода

- Приглашение: `>` (ровно так, как в примерах дизайна).
- Значения печатаются как в примерах дизайна: `6`, `11` — без префиксов
  и без кавычек вокруг чисел.
- Ошибки лексера/парсера: `file:line:col — <message>`.
- Ошибки runtime: `raised (...)` + опциональная стек-подсказка.
- `check-examples` отбрасывает результат строк с `>` в fenced-блоках
  ` ```brig repl ` эвристикой A2.

## Пример: минимальный REPL-цикл

Правильная форма (упрощённо, для навигации по коду):

```go
// cmd/brig/repl.go
func RunREPL(in io.Reader, out io.Writer) error {
    rl, _ := readline.NewEx(&readline.Config{Prompt: "> "})
    defer rl.Close()

    sess := repl.NewSession() // держит области строк, НЕ мутирует старые
    for {
        line, err := rl.Readline()
        if err == readline.ErrInterrupt { continue }
        if err == io.EOF { return nil }

        // многострочка — по A5, не по «склейке строк»
        src := repl.CollectLogicalLine(line, rl, sess)

        res, err := sess.EvalLine(src) // новая область на каждый вызов
        switch {
        case err != nil:
            fmt.Fprintf(out, "%s\n", formatDiag(err))
        case res != nil:
            fmt.Fprintf(out, "%s\n", res)
        }
    }
}
```

При правке REPL **обязательно**:

1. Проверить, что новая область создаётся на каждый ввод (не переиспользуется).
2. Проверить N12-снимок: `x = 1  // замыкание  // x = 2` — замыкание видит `1`.
3. Проверить многострочку на всех пяти случаях (см. выше).
4. Убедиться, что exit codes не поменялись (см. тесты).

## Структура

| Файл                         | Назначение                                                                  |
| ---------------------------- | --------------------------------------------------------------------------- |
| `cmd/brig/main.go`           | Entry point, dispatch (cobra или рукописный)                                |
| `cmd/brig/repl.go`           | Цикл REPL; readline: `github.com/chzyer/readline` или аналог                |
| `cmd/check-examples/main.go` | Отдельный тул по A2                                                         |
| `internal/prelude/io.go`     | `print`/`eprint`/`log` — единственное место, где зафиксирован stdout/stderr |
| `cmd/brig/*_test.go`         | Тесты exit-кодов, формата диагностик, идемпотентности `fmt`                 |

## Сериализация / форматы (что тестировать)

- **`fmt` round-trip:** `parse(fmt(src))` эквивалентно `parse(src)`; `fmt` идемпотентен.
- **Диагностики:** формат `file:line:col — message` — стабилен, включая `col` с 1, а не с 0.
- **Exit codes:** покрыты табличными тестами (по одному на код).
- **REPL-вывод:** строки без префиксов, значения — как в дизайне.

## Частые ошибки

- **REPL-переменные мутируются последующими строками** — ломает N12.
  Симптом: замыкание, созданное на строке 1, видит значение из строки 3.
- **Exit code 1 для uncaught raise** — должно быть 2. Симптом: CI путает
  парсинг и runtime.
- **`brig run` без `fn main()`** — должен ругаться; симптом: тихий exit 0.
- **REPL склеивает входные строки без учёта offside** — `fn` ждёт INDENT,
  а не `\n`. Симптом: однострочный `fn f() = 1` работает, многострочный — нет.
- **Диагностика без `col` или с `col = 0`** — не совпадает с форматом
  `file:line:col`. Симптом: golden-тесты диагностик падают на первом же кейсе.
- **`fmt` не идемпотентен** — после второго прохода меняется вывод. Симптом:
  тест «fmt(fmt(x)) == fmt(x)» ловит это на нестандартных отступах.
- **`log` уходит то в stdout, то в stderr** — источник выбора размазан по
  коду. Симптом: нестабильные интеграционные тесты вывода.
- **Замыкание захватывает имя, а не значение** — классическая ошибка
  реализации N12; ловится тестом `TestREPLClosures`.
