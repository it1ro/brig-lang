Да, и это важно для позиционирования Brig: **акторная модель — не свойство функциональных языков, а отдельная парадигма конкурентности**, которая может комбинироваться с FP, а может и нет. Большинство функциональных языков **не имеют акторов** как части языка.

## Функциональные языки без акторной модели

### Чисто функциональные, без акторов вообще

- **Haskell** — ленивый, чистый. Конкурентность через `forkIO`, `MVar`, `STM`, `async`. Акторы — только библиотеки (Cloud Haskell, Akka-подобные), не часть языка.
- **Elm** — чистый, фронтенд. Конкурентность через `Cmd`/`Sub`, никаких акторов.
- **PureScript** — Haskell-подобный, без акторов.
- **Idris** — зависимые типы, без акторов.
- **Agda** — proof assistant, без акторов.

### ML-семейство

- **OCaml** — функциональный, конкурентность через потоки/`Domain`/библиотеки (Lwt, Eio). Акторы — только библиотеки.
- **Standard ML** — без акторов.
- **F#** — есть `MailboxProcessor` (актор-подобный), но это **библиотека**, не часть языка. Основная конкурентность — `Async`, `Task`, `Agent`.
- **ReasonML** — OCaml-синтаксис, без акторов.

### Lisp-семейство

- **Clojure** — функциональный, конкурентность через **CSP** (`core.async`), `atom`, `ref`, `agent` (не акторы в Erlang-смысле). Акторы — только библиотеки.
- **Scheme/Racket** — без акторов в ядре.
- **Common Lisp** — без акторов.

### Строгие функциональные

- **Scala** — FP + OOP, конкурентность через `Future`, `Akka` (библиотека), `ZIO`, `cats-effect`. Акторы — **библиотека Akka**, не язык.
- **Kotlin** — FP-элементы, корутины, без акторов в ядре.
- **Swift** — FP-элементы, `async/await`, `Actor` (с 5.5!) — но это модель **изоляции состояния**, а не Erlang-акторы с mailbox.

### Языки с акторами в ядре

- **Erlang** — акторы (processes) — основа языка.
- **Elixir** — то же, поверх BEAM.
- **Pony** — акторы + reference capabilities, в ядре.
- **Akka/Scala** — библиотека, но де-факто стандарт.
- **Orleans (C#)** — virtual actors, библиотека/фреймворк.
- **Dart** — `Isolate` — ближе к акторам без общего состояния, но не Erlang-модель.

## Ключевое различие

| Парадигма          | Что общего                           | Что разное                             |
| ------------------ | ------------------------------------ | -------------------------------------- |
| **FP**             | Иммутабельность, функции, композиция | Нет модели конкурентности              |
| **Акторы**         | Изоляция, mailbox, message passing   | Может быть в любом языке               |
| **CSP**            | Каналы, обмен сообщениями            | Другая модель (Go, Clojure core.async) |
| **STM**            | Транзакционная память                | Haskell, Clojure                       |
| **Future/Promise** | Асинхронность                        | Scala, F#, JS                          |

**FP и акторы ортогональны.** Можно иметь:

- FP без акторов (Haskell, OCaml, Elm, Clojure);
- акторы без FP (Erlang — не чистый FP, Pony — да, но это исключение);
- FP + акторы (Elixir — да, но не чистый FP; Brig — да, по дизайну).

## Что это значит для Brig

Brig — **редкая комбинация**:

- **FP-ядро**: иммутабельность, `Option`/`Result`, pattern matching, TCO, `|>`, отсутствие `nil`.
- **Акторы в ядре**: `spawn`, `send`, `recv`, `link`/`watch`, супервизоры, HWM, backpressure.
- **Single binary**: Go-рантайм, `go:embed`, wazero.

Большинство FP-языков дают **только первую часть**. Erlang/Elixir дают **только вторую** (и не являются чисто функциональными в Haskell-смысле). Brig пытается дать **обе** — и это его ниша.

## Почему это важно для позиционирования

Можно сформулировать так:

> **Brig — это функциональный язык, в котором акторы являются частью ядра, а не библиотекой.**

Это отличает его от:

- **Haskell/OCaml/Clojure** — там акторы надо прикручивать;
- **Scala/F#** — там акторы библиотечные;
- **Erlang/Elixir** — там акторы в ядре, но FP не чистый;
- **Go** — там CSP, не акторы, и нет иммутабельности.

И это ровно то, что делает **две мачты** осмысленными:

> **Первая мачта — FP-ядро. Вторая — акторный рантайм. Вместе — Brig.**

То есть метафора двух мачт не только про тюрьму и корабль, но и про **два парадигмальных столпа**, которые в Brig соединены. И это соединение — действительно редкое.
