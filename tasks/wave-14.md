# Wave 14 — REPL как рабочая консоль

[← карта плана](README.md)

**Откуда:**
- решение автора языка от 2026-09-27: REPL из отладочного режима становится
  основным инструментом исследования кода и базой для консоли приложения
  (`brig console` ≈ `iex -S mix`, консоль Calmar ≈ `rails c`);
- research: `web-mvp-research/05-toolchain.md` (`brig console` — S),
  `08-roadmap.md` (`brig console` с `h`), `16-infrastructure.md:76`
  (`./app console` к работающему процессу);
- §11.4 (REPL), §16 (REPL и горячая перезагрузка — Nice).

**Что сейчас:**
- `cmd/brig/repl.go` читает ввод через `bufio.Scanner`: нет редактирования
  строки, истории, Ctrl-R, Tab.
- Продолжение ввода — только по незакрытым скобкам
  (`repl.IsContinuation` → `countUnbalanced`). Offside-блоки
  (`fn`, `match`, `recv`, многострочный `if`) ввести нельзя.
- Одна инструкция на ввод (`repl: expected one statement per line`).
- Ошибка печатается как `! <err>`: без позиции, строки кода и stack trace,
  хотя `vm.ErrRaise.Trace` уже есть.
- Вывод — плоский `Inspect()` в одну строку.
- Команд, доков и «последнего результата» нет.
- Планировщик синхронный: `Scheduler.runMain` (`internal/vm/scheduler.go:521`)
  крутится, только пока исполняется строка. Каждая строка — новый main-актор
  со своим `self()` и ящиком. Между вводами акторы стоят, `recv` без
  отправителя даёт `deadlock`. Консоль с живым сервером на такой модели
  невозможна.

**Решения (автор языка, 2026-09-27):**
1. Редактор строки — свой, поверх `golang.org/x/term` (первая зависимость
   в `go.mod`, только ради raw mode). Готовые readline-библиотеки не берём:
   многострочный offside-ввод и подсветка по лексеру Brig в их модель не
   ложатся.
2. Консольные команды — функции-хелперы в стиле iex: `h(Map.get)`, `v(3)`,
   `recompile()`, `flush()`. Префикс `:` не подходит: `:help` — валидный
   атом. Хелперы — обычные вызовы, их можно комбинировать; в remote console
   они работают так же; фреймворк добавляет свои (`routes()`, `app()`).
3. REPL — долгоживущий актор со стабильным pid и ящиком. Планировщик
   работает между вводами, Ctrl-C прерывает текущий ввод, сессия остаётся
   жива.

**Вход:**
- T-137 (#195), компиляция программы из нескольких модулей — для T-207;
- остальные задачи волны от других волн не зависят.

**Зачем:** Brig — язык с акторами и неизменяемыми данными. Его основной
рабочий цикл — «спавнить, послать, посмотреть» и «взять данные,
преобразовать, посмотреть», и оба идут в консоли. Для Calmar консоль —
главный инструмент отладки живого приложения. Ядро сессии без привязки к
транспорту сразу закладывает remote console и LSP.

**Выход:**
- в `brig repl` вводятся многострочные `fn`/`match`/`recv`, работают
  история, Ctrl-R, Tab и подсветка;
- значения печатаются по ширине терминала, ошибки — с позицией, строкой
  кода и stack trace;
- `self()` стабилен между вводами, заспавненные акторы работают в фоне,
  `flush()` показывает ящик, Ctrl-C не убивает сессию;
- `h`, `i`, `v`, `bindings`, `reset`, `load`, `time`, `dis`, `recompile`
  работают; фреймворк регистрирует свои хелперы;
- `brig console` в проекте поднимает граф модулей.

**Вне волны:** remote console к работающему процессу (сокет 0600,
`./app console`) ставится на `repl.Session` (T-201), когда появится
`brig build`. Хелперы Calmar (`routes()`, `app()`) — в пакете Calmar через
API из T-206.
