# Brig — консолидированный дизайн языка v0.4.4

Документ фиксирует консолидированное состояние дизайна Brig. **Заменяет v0.4.3 целиком.** Изменения относительно v0.4.3 — результат закрытия блокеров B1–B9 и новых вопросов N1–N12. Изменённые места помечены ⚠. Нумерация разделов сохранена; добавлен **§16 «Формальная грамматика»**, который является нормативным источником для `brig.ebnf`.

**Референсный интерпретатор Brig реализуется на Go (Golang)** — см. §13.

---

## 0. Принципы

1. Лаконичность без двусмысленности — сокращение допустимо, только если читатель угадает смысл.
2. Один способ для одной задачи.
3. Явное лучше неявного.
4. Отсутствие значения — всегда в типе: `Option`, `Result`, `()` как Unit. **`nil` в языке нет.**
5. Акторы — рантайм, модули — неймспейсы. Не смешивать.
6. Indent-driven для кода; скобки — для данных: `[]` списки, `()` кортежи, `{}` записи, `%[...]` векторы, `%{...}` мапы. Offside-блоки активны и внутри бракетных литералов (см. §1).
7. Функции сравниваются по identity; записи — гибридно, номинально или структурно (см. §2.10).
8. Рост очереди видим (`mailbox_size`) и ограничен (HWM). Переполнение — контейнированное падение актора, наблюдаемое через `watch`. Скрытых stash-механизмов уровня языка нет.
9. `..` имеет одну идею («остаток / развёртка») во всех позициях, где применим (см. §3).
10. Примеры — валидный код, прогоняются через парсер, сгенерированный из §16 / `brig.ebnf`.
11. VM гарантирует TCO для хвостовых вызовов, **кроме вызовов внутри области активного `ensure`**: код `ensure` обязан выполниться после возврата, что требует сохранения кадра. Вне `ensure` гарантия безусловна (см. §8.4, §13).
12. Единственное присваивание: имя связывается один раз в **лексической области** (см. §4.6), rebinding внутри области запрещён. Вложенная область может затенять имя внешней (shadowing, §4.6). В REPL каждая введённая строка — новая top-level область (§10.7).
13. **Иммутабельность — языковая гарантия.** Все значения неизменяемы; «изменяющие» операции коллекций (`Vec.set`, `Map.put`) возвращают новое значение, старое остаётся доступным. Мутация — только через замену состояния актора. Это не оптимизация, а семантическое свойство, на которое опираются §3 (спред), §13 (общий heap), §13 (модель памяти).

## 1. Синтаксис блоков, отступы, комментарии

- Только пробелы, tabs запрещены. Пустые строки не закрывают блок. Отступ комментария не учитывается.
- Продолжение строки — по ведущему оператору, **закрытый список**: `|> and or + - * / ** div rem to == != < > <= >= ..`. Оператор-продолжение обязан быть первым токеном строки; отступ строки-продолжения — строго больше отступа первой строки стейтмента. `<-` из списка убран: его позиция полностью фиксирована грамматикой `with` (§7).
- Скобки — для данных и вложенных выражений внутри выражения.
- Однострочная форма допустима только там, где однозначна (см. §6, §7, §10.4).
- **Комментарии** — однострочные, `#` до конца строки.
- **Пробел перед `(` незначим.** `f (a, b)` ≡ `f(a, b)` — вызов с двумя позиционными аргументами. Скобки после идентификатора (или после постфиксного `.name`, `[...]`) — **всегда** список аргументов вызова. Чтобы передать кортеж одним аргументом — **двойные скобки**: `f((a, b))`. Пробел внутри и снаружи `(`, `[`, `{` декоративен.
- **Offside внутри бракетных литералов.** Внутри `(...)`, `[...]`, `{...}`, `%[...]`, `%{...}` переносы строк разрешены без оператора-продолжения. Элементы разделяются запятой **или** переносом строки; висячая запятая перед закрывающей скобкой разрешена.
- ⚠ **Якорь offside-блока.** Базовый отступ offside-блока (`fn`, `match`, `recv`, `with`, `trap`, `if`) считается от отступа **токена, открывающего блок** (`fn`, `match`, `recv`, `with`, `trap`, `if`), а не от строки открывающей скобки. Тело блока начинается со строки, следующей за открывающим токеном, и должно иметь отступ строго больше. Блок заканчивается на первом токене с отступом меньше или равным базовому. Это правило работает и внутри `%{...}`, `[...]` и `(...)`: если `fn` появляется в середине строки после `=>`, якорь — сам токен `fn`.
- **Идентификаторы.**
  - `lower_ident`: `[a-z] [a-zA-Z0-9_]*`, опциональный финальный `?` — маркер предиката.
  - `UpperIdent` (типы, конструкторы, модули): `[A-Z] [a-zA-Z0-9_]*`.
  - `_` — wildcard, **не** `lower_ident`, не может быть именем переменной.
- **Формальная грамматика атома.**

  ```
  atom        ::= ":" lower_ident ["?"]
  lower_ident ::= [a-z] [a-zA-Z0-9_]*
  ```

  Атомы не могут содержать `?` в середине, начинаться с `_` или `PascalCase`.

- **Зарезервированные слова:** `fn match recv with else if then after when alias import module type ensure trap and or not div rem to true false as`.
  `raise`/`assert` — функции прелюдии, не keywords. Синтаксис вызова — `raise(x)`, `assert(x)`. `raise((:not_found, id))` — вызов с одним аргументом-кортежем (двойные скобки).
- ⚠ **`=` — стейтмент, не выражение.** `let_bind ::= pattern "=" expr`. `=` не входит в таблицу приоритетов (§5.0). Присваивание-выражение отсутствует.
- ⚠ **Позиция `trap`.** `trap` запрещён в позиции аргумента вызова и в позиции элемента литерала (список, кортеж, мапа, запись). Разрешён только как RHS `let_bind` или как отдельный `expr_stmt`. Это упрощает offside-разбор (см. §8.2, §16).

## 2. Литералы и типы данных

### 2.1 Числа

- `Int` — целое произвольной точности.
- `Float` — IEEE754 double.
- `Decimal` — точная десятичная арифметика, `dec"1.50"`. **(should have)**
- `Rational` — stdlib. **(nice to have)**

**Лексические правила (Must для лексера).**

- `0x`/`0b`/`0o` — только `Int`.
- `_` разрешён только между цифрами: `1_000_000`. Не в начале, не в конце, не рядом с `x`/`b`/`o` или `.`.
- `1e9`, `1.5e-3`, `1E+9` — `Float`.
- `1.5` — `Float`. `1.` и `.5` — ошибка лексера.
- `-1`, `+1` — унарные операторы над `1`, не часть литерала (см. §5.0).
- `dec"..."` — `Decimal`. Тело — десятичный литерал, `_` разрешён.
- `rx"..."` — regex-литерал. **(should have)**

### 2.2 Строки и Bytes

- Интерполяция: `"Привет, \(name)!"`.
- Escape: `\n`, `\t`, `\\`, `\"`, `\(`.
- Строка — UTF-8, всегда валидный.
- Многострочный литерал `"""..."""`. **(should have)**
- **`Bytes`** — `b"\x89PNG"`. **Must**. `Bytes.to_str(b)` / `Str.to_bytes(s)`.
- **Сигилы:** `b"..."`, `dec"..."`, `rx"..."`. Пользовательских сигилов нет.

**Интерполяция `\(...)` (Must для лексера).**

- Границы: от `\(` до соответствующей `)` с учётом вложенности скобок `()`, `[]`, `{}` и вложенных строк.
- Внутри `\(...)` разрешены любые выражения, включая вызовы, литералы и вложенные строки.
- Многострочные выражения внутри `\(...)` разрешены.
- Невалидная UTF-8 в `Str` невозможна by construction; `Bytes.to_str(b)` при невалидной UTF-8 — `raise((:invalid_utf8, b))`.

### 2.3 Кортежи (Tuple)

```brig
t = (1, "a", :ok)
(a, b, c) = t
```

- `()` — Unit.
- `(x)` — группировка.
- `(x,)` — 1-кортеж.
- `..` в кортеже запрещён.
- Равенство — структурное.

### 2.4 Списки (List)

```brig
[1, 2, 3]
```

Паттерны: `[1, ..rest]`, `[1, 2, ..]`, `[1, 2, _]`, `[1, 2, _, ..rest]`. `..`/`..name` — только последним, не более одного раза.

`[1, 2, ..]` в позиции **выражения** — запрещено: `..` без операнда допустим только в паттерне.

### 2.5 Диапазоны — `Range`

```brig
r = 1 to 10
nums = list(1 to 10)
```

⚠ **`Range` — встроенное иммутабельное значение первого класса.** Представляется как `Range{ start: Int, end: Int }`.

- **Равенство** — структурное (`1 to 10 == 1 to 10`).
- **Term order** — сразу после `Bool`, перед атомами (см. §5.3).
- **Паттерны** — в MVP не поддерживаются. `Range` нельзя использовать в позиции `pattern`.
- **Сериализация** — опциональна, формат `{"__range__": [start, end]}`. **(should have)**
- `list(range)` материализует. `list(1 to 1)` → `[1]`.
- Убывающий литеральный range (`1 to 0`, `5 to 1`, `10 to 2`) — **ошибка парсинга**. При вычисляемых границах — runtime `raise((:range_error, (start, end)))`.
- `...` не используется.

### 2.6 Vector

```brig
v = %[1, 2, 3]
v[0]
Vec.set(v, 0, 99)
Vec.push(v, 4)
len(v)
```

- Trie-структура (Clojure-style), O(1) amortized append, O(log32 n) чтение.
- Литерал — `%[...]`.
- Паттерн-матчинг — только по точной длине; `..` не поддерживается.
- `v[0]` вне границ — `raise((:index_out_of_bounds, (idx, len)))`.
- Модуль называется `Vec` — осознанное исключение из правила «модули не сокращаются».

### 2.7 Map

```brig
m = %{ "a" => 1, "b" => 2 }
m["a"]                 # Option
Map.put(m, "c", 3)
m2 = %{ ..m, "c" => 3 }
```

⚠ **Pattern matching — частичный по ключам.** Захват ключа `%{ k => v }` в MVP запрещён. `..` в паттернах Map **запрещён** в MVP.

- `%{ "a" => a }` матчится, если ключ `"a"` есть; остальные ключи игнорируются.
- Отсутствующий ключ в паттерне означает, что пара не требуется для совпадения.
- `m["a"]` возвращает `Option`.

### 2.8 Set

```brig
s = set(1, 2, 3)
```

Паттерн-матчинг — точный. `Queue` — FIFO, Okasaki, stdlib. **(nice to have)**

### 2.9 ⚠ Встроенные варианты `Option`/`Result`

**`nil` исключён.** Нет значения — `Option<T>`. Ошибка — `Result<T, E>`. Нет содержательного значения — `()`.

⚠ **`Option` и `Result` — встроенные алгебраические варианты, а не прозрачные тюплы/атомы.**

- `Ok(1) != (:ok, 1)`.
- `None != :none`.
- `Some(1) != (:some, 1)`.
- Равенство — по тегу и полям (как у номинальных вариантов, §2.10).
- Паттерны — только `Ok(x)`, `Error(e)`, `Some(v)`, `None`.
- Сериализация — с `type_tag`: `{"__type__": "Ok", "value": 1}`. **(should have)**

Внутреннее представление в VM может совпадать с тегированной записью, но семантика — номинальная.

### 2.10 Записи: номинальные и анонимные

- `type User {...}` — номинальная.
- `{ key: value, ... }` — структурная.
- Разные виды друг другу не равны.

**Три формы `type`:**

1. **Вариант-декларация:** `type Result<T, E> { Ok(T), Error(E) }`.
2. **Запись-декларация:** `type User { id: Int, name: Str }`.
3. **Алиас:** `type UserId = Int`.

Различие по первому токену: `{` → вариант/запись (различаются по содержимому: `Name(...)` vs `name:`), `=` → алиас.

⚠ **Синтаксис конструкторов вариантов (N1).**

- Конструктор **без аргументов** — **значение**: `None`, `Red`, `Green`.
- Конструктор **с аргументами** — **функция**: `Some`, `Ok`, `Error`.
- Пользовательские конструкторы работают так же: `type Color { Red, Green, Blue }` даёт три значения; `type Wrapper { Wrap(Int) }` даёт функцию `Wrap`.
- Конструктор можно передавать как функцию: `map(Some, xs)`.

**Формальный синтаксис:**

```
type_decl     ::= "type" TypeName [ "<" GenericParams ">" ] type_body
GenericParams ::= TypeVar { "," TypeVar }
TypeVar       ::= [A-Z] [a-zA-Z0-9_]*
type_body     ::= "{" variant_list "}" | "{" field_list "}" | "=" type_expr
variant_list  ::= variant { "," variant }
variant       ::= ConName [ "(" type_expr { "," type_expr } ")" ]
field_list    ::= field { "," field }
field         ::= lower_ident ":" type_expr
type_expr     ::= TypeName [ "<" type_expr { "," type_expr } ">" ]
                | TypeVar
                | "()"
                | "(" type_expr { "," type_expr } ")"
                | "(" [ type_expr { "," type_expr } ] ")" "->" type_expr
```

⚠ **Параметризация generic-типов — только через `<...>`.** Квадратные скобки `[...]` в позиции типа не используются.

⚠ **Семантика аннотаций типов.** Аннотации `u: User`, `-> Int` — **documentation-only** в MVP: не проверяются ни статически, ни в рантайме. Runtime-контракты — Should (§14).

**Трение с принципом #3.** Аннотации выглядят как контракт, но игнорируются — осознанный компромисс MVP: полу-проверка хуже отсутствия. Фраза «`fn greet(u: User)` не принимает другой тип» **удалена**: она противоречила documentation-only.

Конвертация: `{ ..u }`, `User{ ..r }`. Record update сохраняет вид.

Сериализация:

```brig
Json.encode(User{ id: 1 })                       # {"id": 1}
Json.encode(User{ id: 1 }, { type_tag: true })   # {"__type__": "User", "id": 1}
```

### 2.12 As-паттерны

`pattern as name` — деструктурировать аргумент **и** сохранить целое значение:

```brig
fn foo((:ok, _) as full) -> full
```

Разрешён в параметрах `fn`, `match`, `recv`, `with`. **(should have)**

### 2.13 ⚠ Предопределённые имена типов

Следующие имена типов доступны без `import` и могут использоваться в позиции `type_expr`:

- **Примитивы:** `Int`, `Float`, `Decimal`, `Bool`, `Str`, `Bytes`, `Atom`, `Function`.
- **Коллекции:** `List<T>`, `Vector<T>`, `Map<K, V>`, `Set<T>`, `Tuple<...>`, `Queue<T>`.
- **Варианты:** `Option<T>`, `Result<T, E>`.
- **Специальные:** `()`, `Range`, `Pid`, `Ref`.

`Atom` — тип атомов. `Function` — тип функций; сериализация не поддерживается (§11). `Pid`/`Ref` — opaque-значения, сериализация не поддерживается.

## 3. Оператор `..`: унифицированная семантика

**Связывание** (паттерн):

- Только последним элементом, не более одного раза.
- Только в `List`-паттернах: `[1, ..rest]`.
- ⚠ В `Map`-паттернах и record-паттернах **запрещён в MVP**. Частичность Map/record выражается отсутствием ключей/полей в паттерне (см. §2.7, §2.10).
- `Tuple`/`Vector` эту роль не поддерживают.

**Конструирование** (построение значения):

- В любом количестве, в любой позиции.

```brig
[0, ..xs, 99]
{ ..user, name: "Bob" }
{ ..a, ..b, x: 1 }
%{ ..m, "c" => 3 }
f(head, ..items, tail)
```

Правило: **связывание — `..` только в конце и один раз; конструирование — `..` где угодно и сколько угодно.**

**Порядок операций при вызове со спредом:**

1. **Спред:** список разворачивается в позиционные аргументы.
2. **Диспетчизация клоза:** первый совпавший клоз выигрывает.
3. **Авто-raise:** если ни один не совпал — `(:function_clause, args)` на финальном списке аргументов.

Спред данных внутри спреда аргументов (`f(..[0, ..xs, 99])`) обрабатывается рекурсивно.

⚠ **`..` и pipe.** `..` в аргументах вызова разрешён, в том числе в pipe RHS: `xs |> f(..ys)` → `f(xs, ..ys)`.

## 4. Функции

### 4.1 Мультиклозные функции

```brig
fn classify(0) -> "zero"
fn classify(1) -> "one"
fn classify(n) -> "many"
```

Guards через `when`:

```brig
fn classify(n) when n > 0 -> "positive"
fn classify(0)             -> "zero"
fn classify(n)             -> "negative"
```

Ни один клоз не подошёл — авто-raise `(:function_clause, args)` (см. §8.3).

**Область `when`-guards.** Разрешён:

- В мультиклозных `fn` (модуль и локальные).
- В ветках `recv`.
- **Не разрешён** в `match` и в `with`/`else`, и в лямбдах.

Guard — подмножество выражений без побочных эффектов. Если guard падает — авто-raise `(:guard_failed, ...)`.

### 4.2 Лямбды

**Короткая:**

```brig
pow = x -> x**2
nums |> map(x -> x * 2)
```

⚠ **Пустая лямбда — канон `() -> expr`.** Форма `fn -> expr` **убрана**.

```brig
thunk = () -> spawn_linked(() -> counter_loop(0))
```

**Полная:**

```brig
fn (x) ->
    y = x * 2
    y + 1
```

⚠ **Паттерны в параметрах лямбды.** Разрешены в полной лямбде: `fn ((:ok, v)) -> ...`. В короткой лямбде `x -> ...` параметр — только `lower_ident`. **(should have)**

⚠ **Границы короткой лямбды (N2).** Тело короткой лямбды `x -> expr` заканчивается на ближайшем токене, который не может быть частью выражения на этом уровне приоритета: `,`, `)`, `]`, `}`, `NEWLINE`. Внутри скобок — до `,` или закрывающей скобки. Вне скобок — до `NEWLINE`.

Лямбда, связанная с именем, — значение-функция. **Взаимная рекурсия замыканий запрещена** — для неё только локальные `fn` (§4.5).

### 4.3 Вариадические параметры и спред аргументов

```brig
fn log_all(..args) ->
    args |> List.each(log)

fn main() ->
    log_all(1, 2, 3)

fn sum()          -> 0
fn sum(x, ..rest) -> x + sum(..rest)

fn main() ->
    nums = [1, 2, 3]
    sum(..nums)
```

`..args` собирается в `List`. `..rest` разворачивается из `List`.

### 4.4 Приоритет `**`, равенство функций

`-x**2 = -(x**2)`, `2**3**2 = 2**(3**2)`. Функции — identity equality.

### 4.5 Локальные именованные функции

```brig
fn pow(base, exp) ->
    fn go(acc, 0) -> acc
    fn go(acc, n) -> go(acc * base, n - 1)
    go(1, exp)
```

Только в начале тела; вперёд-ссылки свободны (взаимная рекурсия разрешена).

### 4.6 Лексическое связывание и shadowing

Единое правило для всех мест, где имя связывается: параметры функций, локальные `fn`, бинды в `match`/`recv`/`with`, параметры лямбд, top-level декларации модуля.

> **Правило.** Имя связывается один раз в **лексической области** (принцип #12). Внутри одной области повторное связывание того же имени — ошибка парсинга. **Вложенная область** может затенять имя внешней: новое связывание видно от точки связывания до конца вложенной области; внешнее связывание после этого не видно. Затенение — не ошибка, но компилятор **выдаёт info-диагностику** при затенении имени прелюдии (§9.1). Затенение не-прелюдийных имён диагностики не вызывает.

Пример-контроль:

```brig
fn main() ->
    x = 1
    f = fn (x) -> x + 1        # параметр x затеняет внешний — OK
    g = fn () ->
        x = 2                   # локальный x затеняет внешний — OK
        x + 1
    (f, g)
```

⚠ **REPL-замыкания — лексический снимок (N12).** Замыкание захватывает связывание своей строки. Позднее `x = 10` в следующей строке не влияет на ранее созданное замыкание.

## 5. Операторы

### 5.0 Таблица приоритетов

| Уровень | Операторы                    | Ассоц.    |
| ------- | ---------------------------- | --------- |
| 2       | `or`                         | left      |
| 3       | `and`                        | left      |
| 4       | `==` `!=` `<` `>` `<=` `>=`  | non-assoc |
| 5       | `\|>`                        | left      |
| 6       | `to`                         | non-assoc |
| 7       | `+` `-`                      | left      |
| 8       | `*` `/` `div` `rem`          | left      |
| 9       | `**`                         | right     |
| 10      | унарный `-`, `not`           | prefix    |
| 11      | постфиксные: `.`, `()`, `[]` | left      |

⚠ **Не в таблице:** `=`, `:`, `->`, `..`, `as`, `=>`. `=` — стейтмент (§1). `->` — lowest precedence, right-assoc, тело до конца выражения/блока (§4). `..` и `as` — не операторы, а маркеры паттернов/спредов. `=>` — только в `map_literal`.

**Свойства:**

- `|>` (5) выше сравнений (4): `a |> f == c` → `(a |> f) == c`.
- `to` (6) выше `|>` (5): `1 to 10 |> list` → `(1 to 10) |> list`.
- Сравнения и `to` — non-assoc: `a == b == c` и `1 to 2 to 3` — **ошибка парсинга**.
- **Больший номер уровня связывает сильнее.**
- Пробел перед `(` незначим (§1).

### 5.1 Логические

`and`/`or`/`not`, `not > and > or`, short-circuit, всегда `Bool`.

```brig
import Option
x = opt |> Option.unwrap_or(default_value)
```

### 5.2 Арифметика

`+ - * / **`, `div`, `rem`. `%` нет.

⚠ **Правила (Must для VM):**

- `/` всегда возвращает `Float`.
- Деление на ноль — `raise((:division_by_zero, ()))`.
- `div` — целочисленное деление к нулю; деление на ноль — `raise((:division_by_zero, ()))`.
- `rem` — знак результата следует за делимым (`-7 rem 3 == -1`, `7 rem -3 == 1`).
- Переполнение `Int` — не происходит (произвольная точность). Стоимость и лимиты — на усмотрение рантайма.
- `v[i]` вне границ — `raise((:index_out_of_bounds, (i, len)))`. То же для `Bytes`/`Str` (индексация по кодпоинту для `Str`, по байту для `Bytes`, возвращает `Int`).

### 5.3 Сравнение и term order

`==`, `!=`, `<`, `>`, `<=`, `>=`.

**`<` тотален, `==` структурен.**

**Числа.** `Int`/`Float` — один домен. `Decimal`:

- `Decimal × Decimal` — точно.
- `Decimal × Int` — по значению.
- `Decimal × Float` — ошибка (`:type_error`).

⚠ **Term order (обновлён):**

1. число (`Int`/`Float`/`Decimal`, кроме пары `Decimal`↔`Float`)
2. `Bool` — `false < true`
3. `Range` — по `(start, end)` лексикографически
4. атом — лексикографически
5. `Bytes` — по байтам
6. `Str` — по кодпоинтам
7. кортеж (`()` — наименьший)
8. `Vector` — длина, затем поэлементно
9. `List` — длина, затем поэлементно
10. `Map` — размер, затем по отсортированным парам
11. `Set` — размер, затем по отсортированным элементам
12. номинальная запись — по имени типа, затем по полям
13. встроенные варианты `Ok`/`Error`/`Some`/`None` — по тегу, затем по полям (порядок тегов: `None < Some`, `Ok < Error`)
14. анонимная запись — по полям
15. `Function` — по identity (адрес, нестабилен между запусками)
16. `Pid`, `Ref` — по identity (нестабильно между запусками)

`sort` смешанных списков бросает только при `Decimal` + `Float`.

### 5.4 Pipe

`x |> f(a, b)` → `f(x, a, b)` — значение подставляется первым аргументом.

**Запрет акторных примитивов в pipe — статическая проверка парсера.** В качестве правой части `|>` запрещены **все** акторные примитивы прелюдии: `send`, `spawn`, `spawn_linked`, `link`, `watch`, `unwatch`, `self`, `make_ref`, `mailbox_size`. Ошибка — на этапе разбора. Разрешённые формы RHS: `f`, `f(a)`, `M.f(a)`, `obj.method(a)`. Частично применённые формы без имени — ошибка.

## 6. `if` — синтаксический сахар над `match`

```brig
if ready
    start()
else
    wait()
```

≡

```brig
match ready
    true  -> start()
    false -> wait()
```

Без `else` — `()`:

```brig
if ready
    start()

# ≡ match ready
#     true  -> start()
#     false -> ()
```

Однострочная форма — только целиком, с обеими ветками:

```brig
x = if ready then start() else wait()
```

**Формальная грамматика:**

```
if_expr  ::= "if" expr NEWLINE INDENT stmt+ DEDENT
           [ "else" NEWLINE INDENT stmt+ DEDENT ]
           | "if" expr "then" expr "else" expr
```

`else` — на том же отступе, что `if` (якорь — токен `if`). `match` всегда блочный.

## 7. `with`/`else`

```brig
fn process(input) -> with
    Ok(a) <- validate(input)
    Ok(b) <- transform(a)
    Ok(c) <- save(b)
    Ok(c)
else
    Error(e) -> Error(e)
```

Binds только в начале; тело — с первого statement без `<-`.

**Формальная грамматика:**

```
with_expr    ::= "with" NEWLINE INDENT bind_stmt+ body_stmt+ DEDENT
                 [ "else" NEWLINE INDENT else_branch+ DEDENT ]
bind_stmt    ::= pattern "<-" expr NEWLINE
body_stmt    ::= let_bind | expr NEWLINE
else_branch  ::= pattern "->" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
```

`else` — на уровне отступа `with`. Ветки `else` проверяются по порядку; первая совпавшая выигрывает.

**Семантика `else`:**

1. Отсутствует — пропагация: цепочка возвращает первое несовпавшее значение. Не авто-raise.
2. Присутствует, значение совпало — ветка выполняется.
3. Присутствует, не совпало — авто-raise `(:case_clause, val)`.

`with` работает и на `Option`.

**Эргономическая ловушка (отсутствие `else`).** Типы documentation-only (§2.10), поэтому `with` без `else` не проверяет форму несовпавшего значения — любое значение «пролетает» наружу. Осознанный выбор в духе Elixir.

## 8. Обработка ошибок

### 8.1 Result/Option

```brig
type Result<T, E> { Ok(T), Error(E) }
type Option<T>    { Some(T), None }
```

⚠ **Встроенные алгебраические варианты.** `Ok(1) != (:ok, 1)`, `None != :none`, `Some(1) != (:some, 1)`. Равенство — по тегу и полям. Паттерны — только по конструкторам. Конструкторы без аргументов (`None`) — значения; с аргументами (`Ok`, `Error`, `Some`) — функции.

### 8.2 `raise`/`trap`

```brig
fn get_user(id) ->
    match db.find(id)
        Some(u) -> u
        None    -> raise((:not_found, id))
```

⚠ Двойные скобки: `raise` принимает ровно один аргумент; кортеж `(:not_found, id)` передаётся как один аргумент.

⚠ **`trap` — самостоятельная форма, не сахар над `trap(fn -> ...)`.** Фраза «блочная форма `trap` — сахар над `trap(fn -> ...)`» **удалена**: она несовместима с `ensure`-клаузами.

⚠ **Формальная грамматика `trap`:**

```
trap_expr    ::= "trap" "(" expr ")"
               | "trap" NEWLINE body_clause (ensure_clause body_clause?)*
body_clause  ::= INDENT stmt+ DEDENT
ensure_clause::= "ensure" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
```

⚠ **Якорь отступа.** `ensure` находится на уровне отступа **стейтмента, открывающего `trap`** (не токена `trap`). Для `result = trap` якорь — `result`.

⚠ **Позиция `trap`.** `trap` разрешён только как RHS `let_bind` или как отдельный `expr_stmt`. Запрещён в позиции аргумента вызова (`f(trap ...)`) и в позиции элемента литерала (`[trap ...]`, `{key: trap ...}`, `%{k => trap ...}`). Это упрощает offside-разбор.

⚠ **Несколько `body_clause` подряд без `ensure` — неоднозначность устранена.** Грамматика: `body_clause (ensure_clause body_clause?)*` — тело начинается с `body_clause`, далее чередуются `ensure` и опциональный `body_clause`.

`trap` ловит любую ошибку внутри, возвращает `Ok(v)` или `Error(e)`.

⚠ **Ошибки в `ensure`.** Все `ensure` выполняются LIFO. Если `ensure` бросает, новая ошибка **заменяет** исходную. Если несколько `ensure` бросают, финальной считается последняя.

### 8.3 Автоматический `raise`

Непокрытый `match`, `recv` или мультиклозная функция бросает автоматически. `with` без `else` — исключение (пропагация, §7); `with` с неполным `else` — авто-raise `(:case_clause, val)`.

Имена авто-raise: `(:function_clause, args)`, `(:case_clause, val)`, `(:recv_clause, msg)`, `(:guard_failed, ...)`, `(:assertion_failed, ())`, `(:type_error, (op, val))`, `(:division_by_zero, ())`, `(:index_out_of_bounds, (idx, len))`, `(:range_error, (start, end))`, `(:invalid_utf8, b)`.

### 8.4 `ensure`/`defer`

`ensure` — клауза на **том же отступе, что стейтмент, открывающий `trap`**. Две формы — `ensure <expr>` или `ensure` + под-блок. Несколько `ensure` допустимы, выполняются LIFO.

Пример с двумя `ensure`, перемежающимися с кодом:

```brig
fn main() ->
    result = trap
        f1 = open("a.txt")
    ensure close(f1)
        f2 = open("b.txt")
    ensure close(f2)
        process(f1, f2)
    result
```

Порядок выполнения при выходе: `close(f2)`, затем `close(f1)`. Грамматика §8.2 это парсит: `body_clause` (`f1 = open(...)`), `ensure_clause` (`close(f1)`), `body_clause` (`f2 = open(...)`), `ensure_clause` (`close(f2)`), `body_clause` (`process(...)`).

**`ensure` и TCO.** Вызовы внутри области активного `ensure` **не гарантируют TCO** (принцип #11). Код `ensure` должен выполниться после возврата, что требует сохранения кадра.

**Область активного `ensure`.** От точки регистрации первого `ensure` до выхода из `trap`. Включает сами `ensure`-клаузы.

**Кросс-акторные ошибки.** Наблюдатель узнаёт о падении только через `watch(pid)`.

**Ошибки в `spawn`.** Без `link`/`watch` падение родителю не видно.

**`trap` внутри ветки `recv`** — рекомендованная идиома.

## 9. Модули и импорты

```brig
module Http.Client
alias Http.Client as Http
import Json
```

⚠ **Формальная грамматика:**

```
module_decl ::= "module" ModuleName NEWLINE
import_decl ::= "import" ModuleName NEWLINE
alias_decl  ::= "alias" ModuleName "as" ModuleName NEWLINE
ModuleName  ::= UpperIdent { "." UpperIdent }
```

- Именование модулей — PascalCase. `Vec` — осознанное исключение (§2.6).
- `import` — весь модуль под собственным именем.
- `alias ... as ...` — под другим именем.
- Без `from x import y`.
- `use`-инъекция макросов не вводится.
- Объявление модуля — `module Http.Client`; по умолчанию файл = модуль.
- **Правило путь-файла → имя модуля.** Относительный путь от корня без `.brig`; каждый сегмент → PascalCase. `json.brig` → `Json`; `http/client.brig` → `Http.Client`. Явный `module ...` переопределяет.
- ⚠ **Top-level модуля — только декларации:** `module`, `import`, `alias`, `type`, `fn`. Top-level `let` и выражения **запрещены** в режиме `module`.
- ⚠ **Entry point — `fn main()` в модуле `Main`.**
- ⚠ **Режимы парсинга.** Один парсер, флаг `mode: module | repl`. В `module` top-level `let`/`expr` — ошибка парсинга. В `repl` — разрешены.

Исключения путь→модуль: `Prelude`, `Main`, `Vec`, builtins — фиксированный список.

### 9.1 Прелюдия

Голые имена без `import`:

- **Коллекции:** `map`, `filter`, `find`, `fold`, `all`, `any`, `len`.
- **Конструкторы:** `list`, `set`.
- **Конверсии:** `to_str`, `to_int`, `to_float`.
- **Акторы/ящик:** `send`, `spawn`, `spawn_linked`, `link`, `watch`, `unwatch`, `self`, `make_ref`, `mailbox_size`.
- **I/O:** `print`, `eprint`, `log`.
- **Эффекты:** `assert`, `raise`, `trap`.
- `not` — оператор.

⚠ **Семантика `assert`.**

```brig
assert(x)  # x: Bool
           # x == true  → ()
           # x == false → raise((:assertion_failed, ()))
           # x не Bool  → raise((:type_error, (:assert_expected_bool, x)))
```

Внутренний тег — атом `:assert_expected_bool`.

⚠ **Политика коллизий имён прелюдии (shadowing).** Shadowing разрешён, но компилятор **выдаёт info-диагностику**:

```
info: `map` shadows prelude function; use `Prelude.map` if prelude was intended
```

Для доступа к прелюдии при shadowing — `import Prelude` даёт `Prelude.map`. Диагностика не блокирует компиляцию.

## 10. Акторы

### 10.1 Модули vs Акторы

Модули — неймспейсы без состояния. Акторы — процессы с PID, состоянием и ящиком.

### 10.2 Создание и связывание

```brig
fn main() ->
    pid1 = spawn(() -> ...)
    link(pid1)
    pid2 = spawn_linked(() -> ...)
    ref = watch(pid2)
    unwatch(ref)
    (pid1, pid2)
```

`watch(pid)` присылает `(:down, ref, reason)` в `recv`.

⚠ **Семантика `link`/`spawn_linked` (MVP).**

- `link(pid)` ≡ `watch(pid)` без возврата ref. То есть **наблюдение**, а не автоматическая смерть.
- `spawn_linked(fn)` ≡ `spawn(fn)` + автоматический `link` со стороны родителя.
- Автоматической эскалации ошибок через границы акторов **нет** — только наблюдение через `:down`.
- `:down` доставляется в **начало очереди** с приоритетом, временно превышая HWM.
- `send` возвращает `Error(:busy)`, когда размер пользовательской очереди ≥ HWM.
- `mailbox_size()` возвращает размер пользовательской очереди.

**Поведение системных сообщений при HWM наблюдателя.**

- Пользовательские сообщения действуют по HWM: `send` возвращает `Error(:busy)`.
- `:down` доставляется всегда, с приоритетом, временно превышая HWM.
- При аномальном переполнении контрольных сообщений — падение `(:system_mailbox_overflow, count)`.

### 10.3 Отправка сообщений

```brig
fn main() ->
    send(worker, :hello)
    send(worker, (:work, data))
```

⚠ `send` возвращает `Result<(), Atom>`: `Ok(())` при успехе, `Error(:busy)` при переполнении. Арность `Result` — два параметра.

### 10.4 `recv`

```brig
recv
    (:value, v) -> v
    (:done)     -> :done
else msg
    log("unhandled: " + to_str(msg))
after 5000 -> :timeout
```

**Offside `else`/`after` формализован.**

> `else` и `after` — клаузы `recv` на **том же отступе, что сам `recv`**. Обе опциональны. Если обе присутствуют — порядок фиксирован: сначала `else`, затем `after`. `after` без `else` разрешён. `else` без `after` разрешён. Более одного `after` — ошибка. Более одного `else` — ошибка.

⚠ **Формальная грамматика `recv`:**

```
recv_expr    ::= "recv" NEWLINE INDENT recv_branch+ DEDENT
                 [ else_clause ] [ after_clause ]
               | "recv" recv_branch              # однострочная форма: одна ветка, без else/after
recv_branch  ::= pattern [ "when" expr ] "->" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
else_clause  ::= "else" lower_ident NEWLINE INDENT stmt+ DEDENT
after_clause ::= "after" expr "->" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
```

Ключевое отличие от v0.4.2: `else`/`after` находятся **вне** блока `INDENT...DEDENT` веток — то есть на уровне отступа `recv`, что соответствует прозе и примеру.

⚠ **Границы однострочной формы (N3).** `recv` в однострочной форме заканчивается на `NEWLINE`. В блочной — на `DEDENT`. То же для `match`, `with`, `trap`.

`after N` — таймаут пустого ящика, `N` — миллисекунды.

`recv!` и stash-механизмы убраны. Оставлен один синтаксис необработанных: `else msg`.

Однострочная форма:

```brig
x = recv (:value, v) -> v
```

⚠ **`else` в `recv` требует `lower_ident`.** `else _ ->` не поддерживается. Для игнорирования сообщения — `else msg` с `msg` в теле (или `_msg`, если имя не нужно).

**Плата за отказ от selective receive.** Прикладная идиома — актор складывает «неожиданные» сообщения в стейт:

```brig
fn worker_loop(state) ->
    recv
        (:reply, id, v) when has_pending(state, id) ->
            worker_loop(resolve_pending(state, id, v))
        (:reply, id, v) ->
            worker_loop(stash(state, id, v))
        (:stop) -> :ok
    else msg
        log("unknown: " + to_str(msg))
        worker_loop(state)
```

### 10.5 `recv` vs `match`

`match` — чистый, не блокирует, всегда блочный; `recv` — блокирует, имеет `after`/`else`.

**Формальная грамматика `match`:**

```
match_expr  ::= "match" expr NEWLINE INDENT match_branch+ DEDENT
match_branch::= pattern "->" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
```

`match` всегда блочный. Guards в `match` не разрешены.

### 10.6 Встроенные акторные примитивы

```brig
send(pid, msg)        # Result<(), Atom>; Error(:busy) при HWM
spawn(() -> ...)
spawn_linked(() -> ...)
link(pid)
watch(pid)            # -> ref; (:down, ref, reason)
unwatch(ref)
self()
make_ref()
mailbox_size()
mailbox_size(pid)     # read-only, racy
```

Correlation-идиома: `make_ref()` в сообщении, ответ матчится по `ref`.

**Формат PID закладывает node-идентификатор** (зарезервированное поле).

⚠ `send` к мёртвому процессу — `Ok(())`, сообщение теряется (как в Erlang). `mailbox_size(pid)` для мёртвого — `Ok(0)`.

### 10.7 REPL

Каждая введённая строка в REPL — **новая top-level лексическая область**. Имена из предыдущих строк видны. Повторное связывание того же имени — shadowing между областями, не rebinding (принцип #12 соблюдён). Внутри одной строки rebinding по-прежнему запрещён.

⚠ **Лексический снимок для замыканий (N12).** Замыкание захватывает связывание своей строки. Поздний `x = 10` в следующей строке не влияет на ранее созданное замыкание.

```brig
> x = 5
> f = () -> x
> x = 10        # shadowing: новая область
> f()
5              # лексический снимок: f видит старый x
> x + 1
11
```

sup = Supervisor.start({

⚠ **Дескриптор MFA — запись, не кортеж.** `{ module: module, function: function, args: args }`. Кортеж `(module, function, args)` не используется.

## 12. Протоколы / Behaviors

**Единственный способ задать Behavior — литерал `Behavior{ handlers: %{...} }`.**

`Behavior` объявлен в stdlib:

```brig
type Behavior { handlers: Map<Atom, Function> }
```

Параметризация `Map<Atom, Function>` — через `<...>`, согласовано с §2.10.

Пример:

```brig
import Map

fn main() ->
    init_state = %{}
    kv_behavior = Behavior{
        handlers: %{
            :get => fn (state, key) ->
                match Map.get(state, key)
                    Some(v) -> (:ok, v)
                    None    -> (:error, :not_found)
            :put => fn (state, key, val) ->
                (:ok, Map.put(state, key, val))
        }
    }
    pid = spawn_behavior(kv_behavior, init_state)
    pid
```

Ключи — атомы. Диспетч по тегу верхнего уровня. Валидация колбэков — вне MVP. **(should have)**

⚠ `spawn_behavior(Behavior, InitState)` — акторный примитив. Определяется здесь; в прелюдию не входит.

## 13. Архитектура рантайма

- **Язык реализации — Go.**
- **Регистровая байткод-VM** (BEAM/Lua-style). Обязателен **дизассемблер** (`--dump-bytecode`) и `line:col` на инструкцию — Must.
- **Память:** общий heap + ссылки на иммутабельные значения, не per-actor heap. Один генеративный GC. Действует, пока язык иммутабелен (§0.13): мутация, FFI, наблюдающий алиасинг или распределённость — триггер пересмотра.
- **Функции в сообщениях** валидны только в shared-heap модели; для распределённости — `{ module: M, function: F, args: A }` (§11, §15.4).
- **Модель планирования: 1 актор = 1 goroutine + редукционные yield-точки.**

  - **1 актор = 1 goroutine.** Лёгкая, масштабируется до миллионов. Параллелизм и M:N горутин на OS-потоки делегированы планировщику Go.
  - **Редукционные yield-точки — обоснование.** С Go 1.14 планировщик Go **сам** выполняет асинхронную преемптивную остановку горутин, включая тесные циклы без вызовов функций. Это не отменяет собственный счётчик редукций, потому что он даёт три вещи, которых Go-планировщик не даёт:
    1. **Детерминированные точки контроля для VM.** На каждой границе редукционного интервала VM проверяет: поступил ли сигнал прерывания (Ctrl+C, shutdown), обновился ли trace-хук (§14, `trace(pid)`), достигнут ли лимит диагностического сэмплирования.
    2. **Отзывчивость супервизора.** `:down` от долго считающего актора, доставленное в его ящик, будет обработано гарантированно не позднее чем через N редукций (N фиксирован конфигурацией VM), **при условии, что актор выполняет `recv`**. Без `recv` сообщение остаётся в ящике. Это гарантия уровня языка для акторов, выполняющих `recv`.
    3. **Задел под N:M.** Если модель эволюционирует в сторону собственного планировщика (§15.10) — редукции уже являются готовой единицей учёта.
  - **`recv` на пустом ящике — блокирующий приём из канала.** Goroutine паркуется.
  - **Связь с §15.10.** Политика блокирующих IO/FFI и число потоков планировщика (M:N) — открытый вопрос. MVP-модель: goroutine + редукционные yield-точки.

- **TCO гарантирован** для само- и общих хвостовых вызовов, **кроме вызовов внутри области активного `ensure`** (§0.11, §8.4).

## 16. Формальная грамматика (нормативный источник)

Раздел является нормативным источником для `brig.ebnf`. `brig.ebnf` извлекается из этого раздела механически и поддерживается в синхронизации.

### 16.1 Программа

```
program      ::= module_decl? import_decl* top_decl*

module_decl  ::= "module" ModuleName NEWLINE
import_decl  ::= "import" ModuleName NEWLINE
alias_decl   ::= "alias" ModuleName "as" ModuleName NEWLINE
ModuleName   ::= UpperIdent { "." UpperIdent }

top_decl     ::= fn_decl | type_decl | alias_decl
```

### 16.2 Стейтменты

```
stmt         ::= let_bind | local_fn_decl | expr_stmt

let_bind     ::= pattern "=" expr NEWLINE
expr_stmt    ::= expr NEWLINE

local_fn_decl::= fn_clause+
```

### 16.3 Функции

```
fn_decl      ::= fn_clause+
fn_clause    ::= "fn" lower_ident "(" [ params ] ")" [ "when" expr ] "->"
                 (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)

params       ::= param { "," param }
param        ::= pattern | ".." lower_ident
```

### 16.4 Выражения

```
expr         ::= lambda_expr | pipe_expr

lambda_expr  ::= lambda_short | lambda_full
lambda_short ::= lower_ident "->" expr
lambda_full  ::= "fn" "(" [ params ] ")" "->"
                 (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
empty_lambda ::= "(" ")" "->" expr    (* частный случай lambda_full *)

pipe_expr    ::= range_expr { "|>" pipe_rhs }
pipe_rhs     ::= call_expr

range_expr   ::= or_expr [ "to" or_expr ]

or_expr      ::= and_expr { "or" and_expr }
and_expr     ::= cmp_expr { "and" cmp_expr }
cmp_expr     ::= add_expr [ ("==" | "!=" | "<" | ">" | "<=" | ">=") add_expr ]
add_expr     ::= mul_expr { ("+" | "-") mul_expr }
mul_expr     ::= pow_expr { ("*" | "/" | "div" | "rem") pow_expr }
pow_expr     ::= unary_expr [ "**" pow_expr ]
unary_expr   ::= [ "-" | "not" ] postfix_expr
postfix_expr ::= primary_expr { postfix_op }
postfix_op   ::= "." lower_ident
              | "." UpperIdent
              | "(" [ args ] ")"
              | "[" expr "]"

primary_expr ::= literal
              | lower_ident
              | UpperIdent
              | "(" expr ")"
              | tuple_literal
              | list_literal
              | vector_literal
              | map_literal
              | record_literal
              | if_expr
              | match_expr
              | recv_expr
              | with_expr
              | trap_expr

args         ::= arg { "," arg }
arg          ::= expr | ".." expr
```

### 16.5 Литералы

```
literal      ::= int_lit | float_lit | decimal_lit
              | string_lit | bytes_lit
              | atom_lit | bool_lit

atom_lit     ::= ":" lower_ident ["?"]
bool_lit     ::= "true" | "false"

tuple_literal ::= "(" expr "," [ expr { "," expr } ] ")"
list_literal  ::= "[" [ list_elem { "," list_elem } [","] ] "]"
list_elem     ::= expr | ".." expr

vector_literal ::= "%[" [ list_elem { "," list_elem } [","] ] "]"

map_literal  ::= "%{" [ map_elem { "," map_elem } [","] ] "}"
map_elem     ::= expr "=>" expr | ".." expr

record_literal ::= [ TypeName ] "{" [ record_elem { "," record_elem } [","] ] "}"
record_elem  ::= lower_ident ":" expr | ".." expr
```

### 16.6 Паттерны

```
pattern      ::= pattern_atom [ "as" lower_ident ]

pattern_atom ::= "_"
              | lower_ident
              | literal
              | constructor_pattern
              | tuple_pattern
              | list_pattern
              | map_pattern
              | record_pattern

constructor_pattern ::= UpperIdent [ "(" [ pattern { "," pattern } ] ")" ]
tuple_pattern       ::= "(" pattern "," [ pattern { "," pattern } ] ")"
list_pattern        ::= "[" [ pattern { "," pattern } [ ".." [lower_ident] ] ] "]"
map_pattern         ::= "%{" [ map_pair { "," map_pair } ] "}"
map_pair            ::= expr "=>" pattern
record_pattern      ::= TypeName "{" [ field_pattern { "," field_pattern } ] "}"
field_pattern       ::= lower_ident ":" pattern
```

### 16.7 Управляющие конструкции

```
if_expr      ::= "if" expr NEWLINE INDENT stmt+ DEDENT
                 [ "else" NEWLINE INDENT stmt+ DEDENT ]
               | "if" expr "then" expr "else" expr

match_expr   ::= "match" expr NEWLINE INDENT match_branch+ DEDENT
match_branch ::= pattern "->" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)

recv_expr    ::= "recv" NEWLINE INDENT recv_branch+ DEDENT
                 [ else_clause ] [ after_clause ]
               | "recv" recv_branch
recv_branch  ::= pattern [ "when" expr ] "->"
                 (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
else_clause  ::= "else" lower_ident NEWLINE INDENT stmt+ DEDENT
after_clause ::= "after" expr "->"
                 (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)

with_expr    ::= "with" NEWLINE INDENT bind_stmt+ body_stmt+ DEDENT
                 [ "else" NEWLINE INDENT else_branch+ DEDENT ]
bind_stmt    ::= pattern "<-" expr NEWLINE
body_stmt    ::= let_bind | expr NEWLINE
else_branch  ::= pattern "->" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)

trap_expr    ::= "trap" "(" expr ")"
               | "trap" NEWLINE body_clause (ensure_clause body_clause?)*
body_clause  ::= INDENT stmt+ DEDENT
ensure_clause::= "ensure" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
```

### 16.8 Типы

```
type_decl     ::= "type" TypeName [ "<" GenericParams ">" ] type_body
GenericParams ::= TypeVar { "," TypeVar }
TypeVar       ::= [A-Z] [a-zA-Z0-9_]*
type_body     ::= "{" variant_list "}"
                | "{" field_list "}"
                | "=" type_expr

variant_list  ::= variant { "," variant }
variant       ::= ConName [ "(" type_expr { "," type_expr } ")" ]
field_list    ::= field { "," field }
field         ::= lower_ident ":" type_expr

type_expr     ::= TypeName [ "<" type_expr { "," type_expr } ">" ]
                | TypeVar
                | "()"
                | "(" type_expr { "," type_expr } ")"
                | "(" [ type_expr { "," type_expr } ] ")" "->" type_expr
```

### 16.9 Лексические правила

```
lower_ident  ::= [a-z] [a-zA-Z0-9_]*
UpperIdent   ::= [A-Z] [a-zA-Z0-9_]*
TypeName     ::= UpperIdent
ConName      ::= UpperIdent

int_lit      ::= "0x" hex_digit { hex_digit | "_" }
               | "0b" bin_digit { bin_digit | "_" }
               | "0o" oct_digit { oct_digit | "_" }
               | dec_digit { dec_digit | "_" }

float_lit    ::= dec_digit { dec_digit | "_" } "." dec_digit { dec_digit | "_" }
                 [ exponent ]
               | dec_digit { dec_digit | "_" } exponent
exponent     ::= ("e" | "E") ["+" | "-"] dec_digit { dec_digit }

decimal_lit  ::= "dec" string_body
string_lit   ::= "\"" { string_char | interpolation } "\""
bytes_lit    ::= "b\"" { bytes_char } "\""
interpolation::= "\\(" expr ")"
```

### 16.10 Соглашения

- `NEWLINE`, `INDENT`, `DEDENT` генерируются лексером по правилам offside (§1). `INDENT`/`DEDENT` — парные токены, соответствующие изменению уровня отступа.
- Якорь offside-блока — отступ токена, открывающего блок (`fn`, `match`, `recv`, `with`, `trap`, `if`).
- `=` — только в `let_bind`. `->` — только в `fn`/`lambda`/`match`/`recv`/`with`/`trap`/`type_expr`. `=>` — только в `map_literal`/`map_pattern`. `<-` — только в `with`.
- `..` — в `list_literal`/`vector_literal`/`map_literal`/`record_literal`/`args`/`list_pattern`/`params`. В `map_pattern`/`record_pattern`/`tuple_literal`/`tuple_pattern` — запрещён.
- Позиция `trap` — только RHS `let_bind` или `expr_stmt`. В `args`, `list_literal`, `tuple_literal`, `map_literal`, `record_literal` — запрещён.
