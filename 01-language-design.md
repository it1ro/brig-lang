# Brig — консолидированный дизайн языка v0.4.3

Документ фиксирует консолидированное состояние дизайна Brig. **Заменяет v0.4.2 целиком.** Изменения относительно v0.4.2 — результат верификационного ревью v0.4.2 (находки G1–G8). Изменённые места помечены ⚠.

**Референсный интерпретатор Brig реализуется на Go (Golang)** — см. §13.

---

## 0. Принципы

1. Лаконичность без двусмысленности — сокращение допустимо, только если читатель угадает смысл.
2. Один способ для одной задачи.
3. Явное лучше неявного.
4. Отсутствие значения — всегда в типе: `Option`, `Result`, `()` как Unit. **`nil` в языке нет.**
5. Акторы — рантайм, модули — неймспейсы. Не смешивать.
6. Indent-driven для кода; скобки — для данных: `[]` списки, `()` кортежи, `{}` записи, `%[...]` векторы, `%{...}` мапы. Offside-блоки активны и внутри бракетных литералов (см. §1).
7. Функции сравниваются по identity; записи — гибридно, номинально или структурно (см. §2.10).
8. Рост очереди видим (`mailbox_size`) и ограничен (HWM). Переполнение — контейнированное падение актора, наблюдаемое через `watch`. Скрытых stash-механизмов уровня языка нет.
9. `..` имеет одну идею («остаток / развёртка») во всех позициях, где применим (см. §3).
10. Примеры — валидный код, прогоняются через парсер.
11. VM гарантирует TCO для хвостовых вызовов, **кроме вызовов внутри области активного `ensure`**: код `ensure` обязан выполниться после возврата, что требует сохранения кадра. Вне `ensure` гарантия безусловна (см. §8.4, §13).
12. Единственное присваивание: имя связывается один раз в **лексической области** (см. §4.6), rebinding внутри области запрещён. Вложенная область может затенять имя внешней (shadowing, §4.6). В REPL каждая введённая строка — новая top-level область (§10.7).
13. **Иммутабельность — языковая гарантия.** Все значения неизменяемы; «изменяющие» операции коллекций (`Vec.set`, `Map.put`) возвращают новое значение, старое остаётся доступным. Мутация — только через замену состояния актора. Это не оптимизация, а семантическое свойство, на которое опираются §3 (спред), §10 (общий heap), §13 (модель памяти).

## 1. Синтаксис блоков, отступы, комментарии

- Только пробелы, tabs запрещены. Пустые строки не закрывают блок. Отступ комментария не учитывается.
- Продолжение строки — по ведущему оператору, **закрытый список**: `|> and or + - * / ** div rem to == != < > <= >= ..`. Оператор-продолжение обязан быть первым токеном строки; отступ строки-продолжения — строго больше отступа первой строки стейтмента. `<-` из списка убран: его позиция полностью фиксирована грамматикой `with` (§7).
- Скобки — для данных и вложенных выражений внутри выражения.
- Однострочная форма допустима только там, где однозначна (см. §6, §7, §10.4).
- **Комментарии** — однострочные, `#` до конца строки.
- **Пробел перед `(` незначим.** `f (a, b)` ≡ `f(a, b)` — вызов с двумя позиционными аргументами. Скобки после идентификатора (или после постфиксного `.name`, `[...]`) — **всегда** список аргументов вызова. Чтобы передать кортеж одним аргументом — **двойные скобки**: `f((a, b))`. Пробел внутри и снаружи `(`, `[`, `{` декоративен.
- **Offside внутри бракетных литералов.** Внутри `(...)`, `[...]`, `{...}`, `%[...]`, `%{...}` переносы строк разрешены без оператора-продолжения. Элементы разделяются запятой **или** переносом строки; висячая запятая перед закрывающей скобкой разрешена. **Offside-блоки внутри этих скобок действуют по обычным правилам**: тело `fn`/`match`/`recv` начинается со строки, следующей за открывающей, и заканчивается на деденте относительно строки открытия блока кода (не относительно строки открытия скобки).
- **Идентификаторы.** Имена переменных/функций — с малой буквы; типов, конструкторов и модулей — PascalCase. Опциональный финальный `?` — маркер предиката; только последний символ имени или атома.
- **Формальная грамматика атома.**

  ```
  atom        ::= ":" lower_ident ["?"]
  lower_ident ::= [a-z] [a-zA-Z0-9_]*
  ```

  Атомы не могут содержать `?` в середине, начинаться с `_` или `PascalCase`.
- **Зарезервированные слова:** `fn match recv with else if then after when alias import module type ensure trap and or not div rem to true false as`.
  `raise`/`assert` — функции прелюдии, не keywords. Синтаксис вызова — `raise(x)`, `assert(x)`. `raise((:not_found, id))` — вызов с одним аргументом-кортежем (двойные скобки).

## 2. Литералы и типы данных

### 2.1 Числа

- `Int` — целое произвольной точности.
- `Float` — IEEE754 double.
- **Литералы:** `0x`/`0b`/`0o`, `1_000_000`, `1e9`.
- `Decimal` — точная десятичная арифметика, `dec"1.50"`. **(should have)**
- `Rational` — stdlib. **(nice to have)**

### 2.2 Строки и Bytes

- Интерполяция: `"Привет, \(name)!"`.
- Escape: `\n`, `\t`, `\\`, `\"`, `\(`.
- Строка — UTF-8, всегда валидный.
- Многострочный литерал `"""..."""`. **(should have)**
- **`Bytes`** — `b"\x89PNG"`. **Must**. `Bytes.to_str(b)` / `Str.to_bytes(s)`.
- **Сигилы:** `b"..."`, `dec"..."`, `rx"..."`.

### 2.3 Кортежи (Tuple)

```brig
t = (1, "a", :ok)
(a, b, c) = t
```

- `()` — Unit.
- `(x)` — группировка.
- `(x,)` — 1-кортеж.
- `..` в кортеже запрещён.
- Равенство — структурное.

### 2.4 Списки (List)

```brig
[1, 2, 3]
```

Паттерны: `[1, ..rest]`, `[1, 2, ..]`, `[1, 2, _]`, `[1, 2, _, ..rest]`. `..`/`..name` — только последним, не более одного раза.

### 2.5 Диапазоны — `to`

```brig
r = 1 to 10
nums = list(1 to 10)
```

Нисходящий — через `(1 to 10) |> List.reverse()`.

**Семантика `list(range)`.** Range — итерируемое; `list(1 to 1)` → `[1]`.

**Убывающие и вырожденные границы — ошибка.** Любой литеральный range с `start > end` (включая `1 to 0`, `5 to 1`, `10 to 2`) — ошибка парсинга. При вычисляемых границах — runtime `(:range_error, (start, end))`.

`...` не используется.

### 2.6 Vector

```brig
v = %[1, 2, 3]
v[0]
Vec.set(v, 0, 99)
Vec.push(v, 4)
len(v)
```

- Trie-структура (Clojure-style), O(1) amortized append, O(log32 n) чтение.
- Литерал — `%[...]`.
- Паттерн-матчинг — только по точной длине; `..` не поддерживается.
- Модуль называется `Vec` — осознанное исключение из правила «модули не сокращаются».

### 2.7 Map

```brig
m = %{ "a" => 1, "b" => 2 }
m["a"]                 # Option
Map.put(m, "c", 3)
m2 = %{ ..m, "c" => 3 }
```

Pattern matching — частичный. Захват ключа `%{ k => v }` в MVP запрещён.

### 2.8 Set

```brig
s = set(1, 2, 3)
```

Паттерн-матчинг — точный. `Queue` — FIFO, Okasaki, stdlib. **(nice to have)**

### 2.9 `nil` исключён

- Нет значения — `Option<T>`.
- Ошибка — `Result<T, E>`.
- Нет содержательного значения — `()`.

Конструкторы — тегированные данные: `Ok(x) ≡ (:ok, x)`, `None ≡ :none`.

### 2.10 Записи: номинальные и анонимные

- `type User {...}` — номинальная.
- `{ key: value, ... }` — структурная.
- Разные виды друг другу не равны.

**Три формы `type`:**

1. **Вариант-декларация:** `type Result<T, E> { Ok(T), Error(E) }`.
2. **Запись-декларация:** `type User { id: Int, name: Str }`.
3. **Алиас:** `type UserId = Int`.

Различие по первому токену: `{` → вариант/запись (различаются по содержимому: `Name(...)` vs `name:`), `=` → алиас.

**Формальный синтаксис:**

```
type_decl     ::= "type" TypeName [ "<" GenericParams ">" ] type_body
GenericParams ::= TypeVar { "," TypeVar }
TypeVar       ::= [A-Z] [a-zA-Z0-9_]*
type_body     ::= "{" variant_list "}" | "{" field_list "}" | "=" type_expr
variant_list  ::= variant { "," variant }
variant       ::= ConName [ "(" type_expr { "," type_expr } ")" ]
field_list    ::= field { "," field }
field         ::= lower_ident ":" type_expr
type_expr     ::= TypeName [ "<" type_expr { "," type_expr } ">" ]
                | "(" type_expr ")"
```

⚠ **Параметризация generic-типов — только через `<...>`.** Использование типа с параметрами как значения типа — тоже `<...>` (`Map<Atom, Function>`). Квадратные скобки `[...]` в позиции типа не используются.

⚠ **Семантика аннотаций типов.** Аннотации `u: User`, `-> Int` — **documentation-only** в MVP: не проверяются ни статически, ни в рантайме. Runtime-контракты — Should (§14).

**Трение с принципом #3.** Аннотации выглядят как контракт, но игнорируются — осознанный компромисс MVP: полу-проверка хуже отсутствия.

`fn greet(u: User)` не принимает ни другой номинальный тип, ни анонимную запись.

Конвертация: `{ ..u }`, `User{ ..r }`. Record update сохраняет вид.

Сериализация:

```brig
Json.encode(User{ id: 1 })              # {"id": 1}
Json.encode(User{ id: 1 }, { type_tag: true })  # {"__type__": "User", "id": 1}
```

### 2.11 Равенство — сводная таблица

| Вид                        | Равенство               | Pattern matching      | Комментарий                   |
| -------------------------- | ----------------------- | --------------------- | ----------------------------- |
| `Int`/`Float`              | численно (смешение)     | точное                | `1 == 1.0` true               |
| `Decimal`                  | точно                   | точное                | `Decimal` vs `Float` — ошибка |
| `Bool`                     | по значению             | точное                | `true`/`false` — примитив     |
| `Str`                      | по кодпоинтам           | точное                | —                             |
| `Bytes`                    | по байтам               | точное                | —                             |
| атом                       | по имени                | точное                | интернированы                 |
| Функция                    | по identity             | —                     | —                             |
| `Tuple`                    | структурно              | точное                | `..` запрещён                 |
| `List`                     | структурно, поэлементно | точное или с `..rest` | O(n)                          |
| `Vector`                   | структурно              | точное, без `..`      | —                             |
| `Map`                      | по набору пар           | **частичное**         | единственное исключение       |
| `Set`                      | по набору элементов     | точное                | —                             |
| `{...}` анонимная          | структурно, по полям    | только с анонимными   | —                             |
| `type X {...}` номинальная | по тегу + полям         | только с тем же `X`   | `X{...} != Y{...}`            |
| `()` Unit                  | единственное значение   | `()`                  | заменяет `nil`                |

### 2.12 As-паттерны

`pattern as name` — деструктурировать аргумент **и** сохранить целое значение:

```brig
fn foo((:ok, _) as full) ->
    # full — весь кортеж (:ok, _); _ — разобранная часть
```

Разрешён в параметрах функции, `match`, `recv`, `with`. **(should have)**

### 2.13 ⚠ Предопределённые имена типов

Следующие имена типов доступны без `import` и могут использоваться в позиции `type_expr`:

- **Примитивы:** `Int`, `Float`, `Decimal`, `Bool`, `Str`, `Bytes`, `Atom`, `Function`.
- **Коллекции:** `List<T>`, `Vector<T>`, `Map<K, V>`, `Set<T>`, `Tuple<...>`, `Queue<T>`.
- **Варианты:** `Option<T>`, `Result<T, E>`.
- **Специальные:** `()` (Unit).

`Atom` — тип атомов (`:ok`, `:none`, ...). `Function` — тип функций; сериализация не поддерживается (см. §11).

## 3. Оператор `..`: унифицированная семантика

**Связывание** (паттерн):

- Только последним элементом, не более одного раза.
- `Tuple`/`Vector` эту роль не поддерживают.

**Конструирование** (построение значения):

- В любом количестве, в любой позиции.

```brig
[0, ..xs, 99]
{ ..user, name: "Bob" }
{ ..a, ..b, x: 1 }
%{ ..m, "c" => 3 }
f(head, ..items, tail)
```

Правило: **связывание — `..` только в конце и один раз; конструирование — `..` где угодно и сколько угодно.**

**Порядок операций при вызове со спредом:**

1. **Спред:** список разворачивается в позиционные аргументы.
2. **Диспетчизация клоза:** первый совпавший клоз выигрывает.
3. **Авто-raise:** если ни один не совпал — `(:function_clause, args)` на финальном списке аргументов.

Спред данных внутри спреда аргументов (`f(..[0, ..xs, 99])`) обрабатывается рекурсивно.

## 4. Функции

### 4.1 Мультиклозные функции

```brig
fn classify(0) -> "zero"
fn classify(1) -> "one"
fn classify(n) -> "many"
```

Guards через `when`:

```brig
fn classify(n) when n > 0 -> "positive"
fn classify(0)             -> "zero"
fn classify(n)              -> "negative"
```

Ни один клоз не подошёл — авто-raise `(:function_clause, args)` (см. §8.3).

**Область `when`-guards.** Разрешён:

- В мультиклозных `fn` (модуль и локальные).
- В ветках `recv`.
- **Не разрешён** в `match` и в `with`/`else`.

Guard — подмножество выражений без побочных эффектов. Если guard падает — авто-raise `(:guard_failed, ...)`.

Пример без заглушек — см. §12.

### 4.2 Лямбды

**Короткая:**

```brig
pow = x -> x**2
nums |> map(x -> x * 2)
```

**Полная:**

```brig
fn (x) ->
    y = x * 2
    y + 1
```

Лямбда, связанная с именем, — значение-функция. **Взаимная рекурсия замыканий запрещена** — для неё только локальные `fn` (§4.5).

### 4.3 Вариадические параметры и спред аргументов

```brig
fn log_all(..args) ->
    args |> List.each(log)

log_all(1, 2, 3)

fn sum()          -> 0
fn sum(x, ..rest) -> x + sum(..rest)

nums = [1, 2, 3]
sum(..nums)
```

### 4.4 Приоритет `**`, равенство функций

`-x**2 = -(x**2)`, `2**3**2 = 2**(3**2)`. Функции — identity equality.

### 4.5 Локальные именованные функции

```brig
fn pow(base, exp) ->
    fn go(acc, 0) -> acc
    fn go(acc, n) -> go(acc * base, n - 1)
    go(1, exp)
```

Только в начале тела; вперёд-ссылки свободны (взаимная рекурсия разрешена).

### 4.6 Лексическое связывание и shadowing

Единое правило для всех мест, где имя связывается: параметры функций, локальные `fn`, бинды в `match`/`recv`/`with`, параметры лямбд, top-level декларации модуля.

> **Правило.** Имя связывается один раз в **лексической области** (принцип #12). Внутри одной области повторное связывание того же имени — ошибка парсинга. **Вложенная область** может затенять имя внешней: новое связывание видно от точки связывания до конца вложенной области; внешнее связывание после этого не видно. Затенение — не ошибка, но компилятор **выдаёт info-диагностику** при затенении имени прелюдии (§9.1). Затенение не-прелюдийных имён диагностики не вызывает.

Пример-контроль:

```brig
x = 1
fn f(x) -> x + 1        # параметр x затеняет внешний — OK
fn g() ->
    x = 2               # локальный x затеняет внешний — OK
    x + 1
```

## 5. Операторы

### 5.0 Таблица приоритетов

| Уровень | Операторы                    | Ассоц.    |
| ------- | ---------------------------- | --------- |
| 2       | `or`                         | left      |
| 3       | `and`                        | left      |
| 4       | `==` `!=` `<` `>` `<=` `>=`  | non-assoc |
| 5       | `\|>`                        | left      |
| 6       | `to`                         | non-assoc |
| 7       | `+` `-`                      | left      |
| 8       | `*` `/` `div` `rem`          | left      |
| 9       | `**`                         | right     |
| 10      | унарный `-`, `not`           | prefix    |
| 11      | постфиксные: `.`, `()`, `[]` | left      |

`<-` удалён из таблицы — фиксируется грамматикой `with` (§7).

Свойства:

- `|>` (5) выше сравнений (4): `a |> f == c` → `(a |> f) == c`.
- `to` (6) выше `|>` (5): `1 to 10 |> list` → `(1 to 10) |> list`.
- Сравнения и `to` — non-assoc.
- `..` и `as` не в таблице.
- Пробел перед `(` незначим (§1).

### 5.1 Логические

`and`/`or`/`not`, `not > and > or`, short-circuit, всегда `Bool`.

```brig
import Option
x = opt |> Option.unwrap_or(default_value)
```

### 5.2 Арифметика

`+ - * / **`, `div`, `rem`. `%` нет.

### 5.3 Сравнение и term order

`==`, `!=`, `<`, `>`, `<=`, `>=`.

**`<` тотален, `==` структурен.**

**Числа.** `Int`/`Float` — один домен. `Decimal`:

- `Decimal × Decimal` — точно.
- `Decimal × Int` — по значению.
- `Decimal × Float` — ошибка (`:type_error`).

**Term order:**

1. число (`Int`/`Float`/`Decimal`, кроме пары `Decimal`↔`Float`)
2. `Bool` — `false < true`
3. атом — лексикографически
4. `Bytes` — по байтам
5. `Str` — по кодпоинтам
6. кортеж (`()` — наименьший)
7. `Vector` — длина, затем поэлементно
8. `List` — длина, затем поэлементно
9. `Map` — размер, затем по отсортированным парам
10. `Set` — размер, затем по отсортированным элементам
11. номинальная запись — по имени типа, затем по полям
12. анонимная запись — по полям
13. `Function` — по identity (адрес, нестабилен между запусками)

`sort` смешанных списков бросает только при `Decimal` + `Float`.

### 5.4 Pipe

`x |> f(a, b)` → `f(x, a, b)` — значение подставляется первым аргументом.

**Запрет акторных примитивов в pipe — статическая проверка парсера.** В качестве правой части `|>` запрещены **все** акторные примитивы прелюдии: `send`, `spawn`, `spawn_linked`, `link`, `watch`, `unwatch`, `self`, `make_ref`, `mailbox_size`. Ошибка — на этапе разбора.

## 6. `if` — синтаксический сахар над `match`

```brig
if ready
    start()
else
    wait()
```

≡

```brig
match ready
    true  -> start()
    false -> wait()
```

Без `else` — `()`:

```brig
if ready
    start()

# ≡ match ready
#     true  -> start()
#     false -> ()
```

Однострочная форма — только целиком, с обеими ветками:

```brig
x = if ready then start() else wait()
```

**Формальная грамматика:**

```
if_expr  ::= "if" expr NEWLINE INDENT stmt+ DEDENT [ "else" NEWLINE INDENT stmt+ DEDENT ]
           | "if" expr "then" expr "else" expr
```

`match` всегда блочный.

## 7. `with`/`else`

```brig
fn process(input) -> with
    Ok(a) <- validate(input)
    Ok(b) <- transform(a)
    Ok(c) <- save(b)
    Ok(c)
else
    Error(e) -> Error(e)
```

Binds только в начале; тело — с первого statement без `<-`.

**Формальная грамматика:**

```
with_expr    ::= "with" NEWLINE INDENT bind_stmt+ body_stmt+ [DEDENT "else" NEWLINE INDENT else_branch+ DEDENT]
bind_stmt    ::= pattern "<-" expr NEWLINE
body_stmt    ::= (let_bind | expr) NEWLINE
else_branch  ::= pattern "->" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
```

**Семантика `else`:**

1. Отсутствует — пропагация: цепочка возвращает первое несовпавшее значение. Не авто-raise.
2. Присутствует, значение совпало — ветка выполняется.
3. Присутствует, не совпало — авто-raise `(:case_clause, val)`.

`with` работает и на `Option`.

**Эргономическая ловушка (отсутствие `else`).** Типы documentation-only (§2.10), поэтому `with` без `else` не проверяет форму несовпавшего значения — любое значение «пролетает» наружу. Осознанный выбор в духе Elixir.

## 8. Обработка ошибок

### 8.1 Result/Option

```brig
type Result<T, E> { Ok(T), Error(E) }
type Option<T>    { Some(T), None }
```

Конструкторы — тегированные данные: `Ok(x) ≡ (:ok, x)`, `Some(v) ≡ (:some, v)`, `None ≡ :none`.

### 8.2 `raise`/`trap`

```brig
fn get_user(id) ->
    match db.find(id)
        Some(u) -> u
        None    -> raise((:not_found, id))
```

⚠ Двойные скобки: `raise` принимает ровно один аргумент; кортеж `(:not_found, id)` передаётся как один аргумент.

Блочная форма `trap` — сахар над `trap(fn -> ...)`. Парсер механически элидирует блок в лямбду.

⚠ **Формальная грамматика `trap` (исправлена относительно v0.4.2):**

```
trap_expr  ::= "trap" "(" expr ")"
             | "trap" NEWLINE body_clause (ensure_clause | body_clause)*
body_clause  ::= INDENT stmt+ DEDENT
ensure_clause::= "ensure" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
```

Тело `trap` — **последовательность body-сегментов и `ensure`-клауз, чередующихся в любом порядке**, начиная с body-сегмента. Это позволяет выразить как классический случай с `ensure` в конце, так и случаи с несколькими `ensure`, перемежающимися с кодом (см. пример §8.4).

`trap` ловит любую ошибку внутри, возвращает `Ok(v)` или `Error(e)`.

### 8.3 Автоматический `raise`

Непокрытый `match`, `recv` или мультиклозная функция бросает автоматически. `with` без `else` — исключение (пропагация, §7); `with` с неполным `else` — авто-raise `(:case_clause, val)`.

Имена авто-raise: `(:function_clause, args)`, `(:case_clause, val)`, `(:recv_clause, msg)`, `(:guard_failed, ...)`, `(:assertion_failed, ())`, `(:type_error, (op, val))`.

### 8.4 `ensure`/`defer`

`ensure` — клауза на **том же отступе, что `trap`**, а не на отступе тела (симметрично `else` в `with`, §7). Две формы — `ensure <expr>` или `ensure` + под-блок. Несколько `ensure` допустимы, выполняются LIFO.

Пример с двумя `ensure`, перемежающимися с кодом:

```brig
result = trap
    f1 = open("a.txt")
ensure close(f1)
    f2 = open("b.txt")
ensure close(f2)
    process(f1, f2)
```

Порядок выполнения при выходе: `close(f2)`, затем `close(f1)`. Грамматика выше это парсит: `body_clause` (`f1 = open(...)`), `ensure_clause` (`close(f1)`), `body_clause` (`f2 = open(...)`), `ensure_clause` (`close(f2)`), `body_clause` (`process(...)`).

**`ensure` и TCO.** Вызовы внутри области активного `ensure` **не гарантируют TCO** (принцип #11). Код `ensure` должен выполниться после возврата, что требует сохранения кадра.

**Кросс-акторные ошибки.** Наблюдатель узнаёт о падении только через `watch(pid)`.

**Ошибки в `spawn`.** Без `link`/`watch` падение родителю не видно.

**`trap` внутри ветки `recv`** — рекомендованная идиома.

## 9. Модули и импорты

```brig
module Http.Client
alias Http.Client as Http
import Json
```

- Именование модулей — PascalCase. `Vec` — осознанное исключение (§2.6).
- `import` — весь модуль под собственным именем.
- `alias ... as ...` — под другим именем.
- Без `from x import y`.
- `use`-инъекция макросов не вводится.
- Объявление модуля — `module Http.Client`; по умолчанию файл = модуль.
- **Правило путь-файла → имя модуля.** Относительный путь от корня без `.brig`; каждый сегмент → PascalCase. `json.brig` → `Json`; `http/client.brig` → `Http.Client`. Явный `module ...` переопределяет.
- **Top-level модуля — только декларации.**
- **Entry point — `fn main()` в модуле `Main`.**

### 9.1 Прелюдия

Голые имена без `import`:

- **Коллекции:** `map`, `filter`, `find`, `fold`, `all`, `any`, `len`.
- **Конструкторы:** `list`, `set`.
- **Конверсии:** `to_str`, `to_int`, `to_float`.
- **Акторы/ящик:** `send`, `spawn`, `spawn_linked`, `link`, `watch`, `unwatch`, `self`, `make_ref`, `mailbox_size`.
- **I/O:** `print`, `eprint`, `log`.
- **Эффекты:** `assert`, `raise`, `trap`.
- `not` — оператор.

⚠ **Семантика `assert`.**

```brig
assert(x: Bool)  # x == true → ()
                 # x == false → raise((:assertion_failed, ()))
                 # x не Bool → raise((:type_error, (:assert_expected_bool, x)))
```

Внутренний тег — атом `:assert_expected_bool`, для единообразия с остальными тегами ошибок.

**Политика коллизий имён прелюдии (shadowing).** Shadowing разрешён, но компилятор **выдаёт info-диагностику**:

```
info: `map` shadows prelude function; use `Prelude.map` if prelude was intended
```

Для доступа к прелюдии при shadowing — `import Prelude` даёт `Prelude.map`. Диагностика не блокирует компиляцию.

Правило shadowing модулей аналогично.

## 10. Акторы

### 10.1 Модули vs Акторы

Модули — неймспейсы без состояния. Акторы — процессы с PID, состоянием и ящиком.

### 10.2 Создание и связывание

```brig
pid = spawn(fn -> ...)
link(pid)
pid = spawn_linked(fn -> ...)
ref = watch(pid)
unwatch(ref)
```

`watch(pid)` присылает `(:down, ref, reason)` в `recv`.

**Поведение системных сообщений при HWM наблюдателя.**

- Пользовательские сообщения действуют по HWM: `send` возвращает `Error(:busy)`.
- `:down` доставляется всегда, с приоритетом, временно превышая HWM.
- При аномальном переполнении контрольных сообщений — падение `(:system_mailbox_overflow, count)`.

### 10.3 Отправка сообщений

```brig
send(worker, :hello)
send(worker, (:work, data))
```

`send` возвращает `Result[()]`: `Error(:busy)` при переполнении.

### 10.4 `recv`

```brig
recv
    (:value, v) -> v
    (:done)     -> :done
else msg
    log("unhandled: " + to_str(msg))
after 5000 -> :timeout
```

**Offside `else`/`after` формализован.**

> `else` и `after` — клаузы `recv` на **том же отступе, что сам `recv`**. Обе опциональны. Если обе присутствуют — порядок фиксирован: сначала `else`, затем `after`. `after` без `else` разрешён. `else` без `after` разрешён. Более одного `after` — ошибка. Более одного `else` — ошибка.

⚠ **Формальная грамматика `recv` (исправлена относительно v0.4.2):**

```
recv_expr    ::= "recv" recv_branches [else_clause] [after_clause]
               | "recv" recv_branch              # однострочная форма: одна ветка, без else/after
recv_branches::= INDENT recv_branch+ DEDENT
recv_branch  ::= pattern [ "when" expr ] "->" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
else_clause  ::= "else" lower_ident NEWLINE INDENT stmt+ DEDENT
after_clause ::= "after" expr "->" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
```

Ключевое отличие от v0.4.2: `else`/`after` находятся **вне** блока `INDENT...DEDENT` веток — то есть на уровне отступа `recv`, что соответствует прозе и примеру. Это тот же паттерн, что в корректной `with_expr` (где `DEDENT` стоит перед `else`).

`after N` — таймаут пустого ящика, `N` — миллисекунды.

`recv!` и stash-механизмы убраны. Оставлен один синтаксис необработанных: `else msg`.

Однострочная форма:

```brig
x = recv (:value, v) -> v
```

**Плата за отказ от selective receive.** Прикладная идиома — актор складывает «неожиданные» сообщения в стейт:

```brig
fn worker_loop(state) ->
    recv
        (:reply, id, v) when has_pending(state, id) ->
            worker_loop(resolve_pending(state, id, v))
        (:reply, id, v) ->
            worker_loop(stash(state, id, v))
        (:stop) -> :ok
    else msg
        log("unknown: " + to_str(msg))
        worker_loop(state)
```

### 10.5 `recv` vs `match`

`match` — чистый, не блокирует, всегда блочный; `recv` — блокирует, имеет `after`/`else`.

**Формальная грамматика `match`:**

```
match_expr  ::= "match" expr NEWLINE INDENT match_branch+ DEDENT
match_branch::= pattern "->" (expr NEWLINE | NEWLINE INDENT stmt+ DEDENT)
```

`match` всегда блочный. Guards в `match` не разрешены.

### 10.6 Встроенные акторные примитивы

```brig
send(pid, msg)        # Result[()], Error(:busy) при HWM
spawn(fn -> ...)
spawn_linked(fn -> ...)
link(pid)
watch(pid)            # -> ref; (:down, ref, reason)
unwatch(ref)
self()
make_ref()
mailbox_size()
mailbox_size(pid)     # read-only, racy
```

Correlation-идиома: `make_ref()` в сообщении, ответ матчится по `ref`.

**Формат PID закладывает node-идентификатор** (зарезервированное поле).

### 10.7 REPL

Каждая введённая строка в REPL — **новая top-level лексическая область**. Имена из предыдущих строк видны. Повторное связывание того же имени — shadowing между областями, не rebinding (принцип #12 соблюдён). Внутри одной строки rebinding по-прежнему запрещён.

```brig
> x = 5
> x + 1
6
> x = 10        # shadowing: новая область
> x + 1
11
```

## 12. Протоколы / Behaviors

**Единственный способ задать Behavior — литерал `Behavior{ handlers: %{...} }`.**

`Behavior` объявлен в stdlib:

```brig
type Behavior { handlers: Map<Atom, Function> }
```

⚠ Параметризация `Map<Atom, Function>` — через `<...>`, согласовано с §2.10 (квадратные скобки в позиции типа не используются).

Пример (используется также в §4.1 как источник валидного кода):

```brig
import Map

KVBehavior = Behavior{
    handlers: %{
        :get => fn(state, key) ->
            match Map.get(state, key)
                Some(v) -> (:ok, v)
                None    -> (:error, :not_found)
        :put => fn(state, key, val) ->
            (:ok, Map.put(state, key, val))
    }
}
pid = spawn_behavior(KVBehavior, init_state)
```

Ключи — атомы. Диспетч по тегу верхнего уровня. Валидация колбэков — вне MVP. **(should have)**

## 13. Архитектура рантайма

- **Язык реализации — Go.**
- **Регистровая байткод-VM** (BEAM/Lua-style). Обязателен **дизассемблер** (`--dump-bytecode`) и `line:col` на инструкцию — Must.
- **Память:** общий heap + ссылки на иммутабельные значения, не per-actor heap. Один генеративный GC. Действует, пока язык иммутабелен (§0.13): мутация, FFI, наблюдающий алиасинг или распределённость — триггер пересмотра.
- **Функции в сообщениях** валидны только в shared-heap модели; для распределённости — `{module, function, args}` (см. §11, §15.4).
- **Модель планирования: 1 актор = 1 goroutine + редукционные yield-точки.**

  - **1 актор = 1 goroutine.** Лёгкая, масштабируется до миллионов. Параллелизм и M:N горутин на OS-потоки делегированы планировщику Go.
  - ⚠ **Редукционные yield-точки — обоснование.** С Go 1.14 планировщик Go **сам** выполняет асинхронную преемптивную остановку горутин, включая тесные циклы без вызовов функций. Это не отменяет собственный счётчик редукций, потому что он даёт три вещи, которых Go-планировщик не даёт:
    1. **Детерминированные точки контроля для VM.** На каждой границе редукционного интервала VM проверяет: поступил ли сигнал прерывания (Ctrl+C, shutdown), обновился ли trace-хук (§14, `trace(pid)`), достигнут ли лимит диагностического сэмплирования. Без собственных точек эти проверки пришлось бы развешивать по байткоду — счётчик централизует их.
    2. **Отзывчивость супервизора.** `:down` от долго считающего актора, доставленное в его ящик, будет обработано гарантированно не позднее чем через N редукций (N фиксирован конфигурацией VM). Это гарантия уровня языка, а не «когда Go-планировщик соизволит».
    3. **Задел под N:M.** Если модель эволюционирует в сторону собственного планировщика (§15.10) — редукции уже являются готовой единицей учёта.
  - **`recv` на пустом ящике — блокирующий приём из канала.** Goroutine паркуется.
  - **Связь с §15.10.** Политика блокирующих IO/FFI и число потоков планировщика (M:N) — открытый вопрос, дальнейшее развитие. MVP-модель: goroutine + редукционные yield-точки.

- **TCO гарантирован** для само- и общих хвостовых вызовов, **кроме вызовов внутри области активного `ensure`** (§0.11, §8.4).
