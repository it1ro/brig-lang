# Brig — DD и PR в одном тикете

Решение дизайна и код по нему живут в одном issue с label `design-decision`.
PR с реализацией открывается на этот же номер (`Closes #<N>`). Отдельного
тикета «сначала решить, потом сделать» нет.

## Сделано ли уже

Смотреть PR этого issue, не код мимо тикета.

Сделано — только если на issue есть PR, который реализует выбранный вариант
(открытый или merged).

Не считать реализацией:

- код, который уже был в репозитории до тикета (`set(...)`, печать trace, `log`, пустой `type Color {}`);
- docs-PR, который только упоминает номер issue;
- PR соседней задачи, который ссылается на DD как follow-up.

Нет такого PR — фича не сделана, даже если кусок поведения уже есть в `main`.

## Как смотреть

Timeline issue: `CrossReferencedEvent` → `PullRequest` на этом номере.
Один запрос на пачку issue, не цикл `gh pr view`.

## Не делать

- Не заводить второй issue на реализацию того же DD.
- Не закрывать DD как «уже есть в коде», если реализующего PR на тикете нет.
- Не класть код DD в чужой PR.
