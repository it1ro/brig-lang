# Brig — лексер (`internal/lexer`)

Нормативный источник: `docs/01-language-design.md` §1, §2, Part II B, D.
Реализация: `lexer.go` (сканеры), `escape.go` (валидация escape/decimal),
`token.go` (типы токенов, keyword-таблица, continuation-операторы).

## Инварианты офсайда (§D), нельзя нарушать молча

- Отступы — только пробелы; таб в отступе — ошибка лексера.
- `indent_stack` начинается с `[0]`; `stmt_indent` — отступ первой строки
  текущего логического стейтмента.
- Единый якорь для ВСЕХ блочных конструкций (`fn`, `match`, `recv`,
  `with`, `if`, `trap`): `base_indent = stmt_indent` строки, содержащей
  ключевое слово. Отдельного правила для `trap` в v0.4.7 **нет** — не
  вносите его обратно.
- Continuation-строка (первый токен — из `continuationOps` в `token.go`)
  не эмитит `NEWLINE`/`INDENT`/`DEDENT`; `stmt_indent` не меняется; отступ
  строки-продолжения обязан быть строго больше `stmt_indent`.
- Внутри скобок (`paren_depth > 0`) офсайд отключён, но `NEWLINE`
  эмитируется как разделитель элементов по правилу
  `shouldEmitBracketNewline` (§D.5): не после `(`/`[`/`{`/`%[`/`%{`/`,`,
  не перед `)`/`]`/`}`/`,`.
- `%[` и `%{` считаются скобками — увеличивают `parenDepth` наравне с
  `(`/`[`/`{` (это было исправлено в v0.4.7, FIX-B — не откатывать).
- Offside-мини-блок внутри скобок (§D.6, A5.4): если внутри `(...)`/
  `[...]`/`{...}`/`%[...]`/`%{...}` встречается `fn`/`match`/`recv`/
  `with`/`trap`/`if`, лексер открывает изолированный стек отступов
  (`blockDepth`), после DEDENT до уровня ≤ `base_indent` — восстанавливает
  внешний скобочный контекст.

## Правила токенизации (§B), edge-cases

- `:` → `ATOM`, если следующий символ `[a-z]` или `_`, **и** предыдущий
  токен не `LOWER_IDENT`/`UPPER_IDENT`/`)`/`]`/`}`; иначе `COLON`.
- Ключевое слово с финальным `?` — всегда `LOWER_IDENT`, не keyword
  (`and?` → identifier, не `KW_AND`).
- `_` — одиночный → `WILDCARD`; `_` + `[a-z]` → `LOWER_IDENT` (`_msg`);
  `_` + `[A-Z0-9]` — ошибка лексера.
- `..` — один токен (`OP_DOTDOT`), не два `.`.
- Числа: `_` разрешён только между цифрами (не в начале/конце, не рядом с
  `x`/`b`/`o`/`.`). `1.` и `.5` — ошибка (`'1.' requires a digit`, `digit
  expected`). `0x_1` и `0b102` — ошибки лексера. Оверфлоу int64 лексер не
  проверяет — Int произвольной точности по спеке; компилятор разбирает
  литерал через `big.Int.SetString` + `runtime.IntBig` с base по префиксу
  (`0x`/`0b`/`0o`, иначе 10) — S-F7 закрыт в T-22 (#16).
- Escape в `Str` (A4.1, `escape.go`): `\n \t \r \0 \\ \" \(` + `\u{H..H}`
  (1–6 hex, ≤ U+10FFFF, не surrogate D800–DFFF). `\xHH` в `Str`
  **запрещён** — это escape только для `Bytes`.
- Escape в `Bytes` (A4.2): `\n \t \r \0 \\ \" \xHH`. Интерполяция `\(` и
  `\u{...}` в `Bytes` **запрещены** — жёсткая ошибка.
- `Decimal` (A4.4, `validateDecimalBody`): `[+-]? digits [. digits]`,
  подчёркивание только между цифрами. `dec"1e9"`, `dec".5"`, `dec"1."` —
  невалидны.
- Интерполяция `\(...)`: границы считаются с учётом вложенных `()[]{}` и
  вложенных строк; незакрытая — ошибка `unclosed interpolation` с
  указанием позиции открывающей `\(`. `SplitInterp(body)` отдаёт части
  строки и исходники выражений; парсер строит `InterpExpr` (S-F1 закрыт
  T-53 #36). Компиляция concat/`to_str` — ✓ T-54 (#37).

## Чек-лист при правке лексера

1. Прочитать соответствующий подраздел Part II B/D/C в
   `docs/01-language-design.md` — не полагаться на память о лексерах
   вообще, здесь много осознанных отступлений от «обычного» дизайна.
2. Добавить/обновить негативный кейс в `testdata/negative/*.brig` +
   `*.err`, если меняется поведение при ошибке.
3. Прогнать `make test-lexer` (узкий таргет) перед `make ci-quick`.
4. Если меняется набор токенов — свериться с B.1 (полный список токенов) и
   не забыть обновить дизассемблер VM, если это влияет на литералы.
5. Не трогать `check-smallint`-инвариант (`Value.Int` приватность) — это
   вне зоны ответственности лексера, но соседний код в этом же модуле
   иногда путают.
6. Fuzz-регрессии лежат в `internal/lexer/testdata/fuzz/FuzzLex/*` — не
   удалять, они защищают конкретные найденные баги (например, unclosed
   string с trailing backslash).

## Частые ошибки при доработке

- Забыть, что `firstToken()` используется и для определения
  continuation-оператора, и для `isBlockOpener` внутри скобок — правки в
  одном месте могут незаметно сломать другое.
- Эмитить `NEWLINE` дважды на границе DEDENT→клауза (`else`/`after`) —
  см. §D.8, таблицу клауз по конструкциям (`trap` клауз после DEDENT не
  имеет вообще, в отличие от v0.4.6).
- Ломать инвариант «поле `intBig` приватно» из соседнего `runtime` при
  парсинге числовых литералов не в этом модуле — просто иметь в виду при
  сквозных изменениях формата чисел.
